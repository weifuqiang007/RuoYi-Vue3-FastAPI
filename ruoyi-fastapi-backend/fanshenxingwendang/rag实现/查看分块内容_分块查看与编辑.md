## 一、需求

文档管理页 → 某文档的操作按钮新增「详情」：
- 点击后展示该文档的全部分块内容。
- 老师可查看、可修改分块文本（"分区内容"）。
- 大知识库下分块列表接口不能超时，需快速显示。

---

## 二、整体设计

```
文档管理页（document/index.vue）
   │ 操作列「详情」按钮
   ▼
右侧抽屉（el-drawer）展示分块表格（分页）
   │ 每行「修改」按钮
   ▼
编辑对话框（el-dialog，textarea）
   │ 保存
   ▼
PUT /rag/chunk  → ChunkService.update_chunk
   │ 1. 取分块  2. 重新向量化(embed_single)  3. 写回 content/token_count/embedding
   ▼
刷新当前页
```

**关键决策：**
| 决策点 | 选择 | 理由 |
|--------|------|------|
| 展示形式 | 右侧抽屉 + 表格 | 分块多、内容长，抽屉比对话框合适 |
| 编辑后处理 | **自动重新向量化** | 否则检索命中旧向量，编辑失去意义 |
| 范围 | 查看 + 修改（不含新增/删除） | 贴合"观看、修改"；删除会牵扯文档 chunk_count 一致性，后续再加 |
| 权限 | 后端 role 限 admin/teacher；前端按钮不限权限 | 与"下载"一致，开箱即用 |
| 列表性能 | **排除 embedding 列 + 分页** | embedding 是超时主因（见第五节） |

### 3.2 分块列表接口（分页 + 排除向量）

```python
# module_rag/dao/chunk_dao.py
@classmethod
async def get_page_by_doc_id(cls, db, doc_id, page_num=1, page_size=20) -> tuple[int, list[RagChunk]]:
    """分页查询。load_only 只查展示列，排除 embedding 向量列。"""
    base_filter = (RagChunk.doc_id == doc_id, RagChunk.del_flag == '0')
    total = (await db.execute(select(func.count(RagChunk.chunk_id)).where(*base_filter))).scalar() or 0
    result = await db.execute(
        select(RagChunk)
        .options(load_only(
            RagChunk.chunk_id, RagChunk.doc_id, RagChunk.kb_id,
            RagChunk.chunk_index, RagChunk.content, RagChunk.token_count, RagChunk.create_time,
        ))
        .where(*base_filter).order_by(RagChunk.chunk_index)
        .offset((page_num - 1) * page_size).limit(page_size)
    )
    return total, list(result.scalars().all())
```

```python
# module_rag/controller/chunk_controller.py
@chunk_controller.get('/list/{doc_id}', summary='获取文档的分块列表')
async def get_chunk_list(doc_id, query_db, page_num=1, page_size=20):
    total, chunks = await ChunkService.get_page_by_doc(query_db, doc_id, page_num, page_size)
    return ResponseUtil.success(data={
        'rows': [ChunkResponseModel.model_validate(c).model_dump() for c in chunks],
        'total': total,
    })
```

### 3.3 修改分块（重新向量化）

```python
# module_rag/service/chunk_service.py
@classmethod
async def update_chunk(cls, db, data: ChunkUpdateModel) -> RagChunk:
    chunk = await ChunkDao.get_by_id(db, data.chunk_id)
    if not chunk:
        raise ServiceException(message='分块不存在')
    if chunk.content == data.content:        # 无变化直接返回，省去向量化调用
        return chunk
    try:
        embedding = await EmbeddingService.embed_single(data.content)   # 重新向量化
    except Exception as e:
        raise ServiceException(message='内容更新失败：向量化服务异常，请稍后重试')
    await ChunkDao.update_content(
        db, chunk_id=data.chunk_id,
        content=data.content, token_count=len(data.content), embedding=embedding,
    )
    return chunk
```

修改保存后调用 `loadChunkPage()` 刷新**当前页**（保持页码，不跳回第 1 页）。

## 五、性能优化：为什么大文档会超时，怎么修

### 5.1 根因：embedding 向量列被全量拉取

初版 `ChunkDao.get_by_doc_id` 用 `select(RagChunk)`，会把每条分块的 **1024 维 embedding 向量**（约 4KB/条）全部从 DB 拉进内存并构建 ORM 对象，再 JSON 序列化。

> 注意：`ChunkResponseModel` 虽然没序列化 embedding 字段，但 SQLAlchemy 在 `select(RagChunk)` 时已经把向量捞上来了——VO 只控制输出，不控制查询。

一个几百上千分块的文档 → 几 MB 向量 + 全文 content → 前端 axios 10s 超时。

### 5.2 两层修复

| 层级 | 手段 | 效果 |
|------|------|------|
| 查询 | `load_only(...)` 只取展示列，**不查 embedding** | 单次查询体积从「向量×N + 文本×N」降到「文本×N」 |
| 接口 | 分页 `offset/limit`，默认每页 20 | 单次响应有界，前端不渲染上千行 |

两者叠加：响应体积从可能几 MB 降到几十 KB 级，接口稳定在百毫秒内。

### 5.3 为什么不用项目的 `PageUtil.paginate`

`PageUtil.paginate` 会用 `CamelCaseUtil.transform_result` 把字段转成 **camelCase**（`chunkIndex`、`docId`），而 `module_rag` 全程用 **snake_case**（`chunk_id`、`chunk_index`）。为保持模块内一致，本接口**手动分页**，不走 PageUtil。

## 六、数据模型回顾（rag_chunk）

| 字段 | 类型 | 说明 |
|------|------|------|
| chunk_id | BIGSERIAL PK | 分块主键 |
| doc_id / kb_id | BIGINT | 所属文档/知识库 |
| chunk_index | INTEGER | 分块序号 |
| content | TEXT | 分块文本（可编辑） |
| token_count | INTEGER | 字符/Token 数 |
| embedding | vector(1024) | 向量（列表接口不查；编辑后重算） |
| metadata | JSONB | 元数据（页码、类型等） |
| del_flag | CHAR(1) | 删除标志 |

## 八、验证

1. 重启后端（controller 自动注册）、前端热更新。
2. 文档管理 → 点「详情」→ 抽屉分页展示分块。
3. 翻页 / 改每页条数 → 正常加载，不超时。
4. 选大文档（分块多的）→ 接口快速返回（验证排除 embedding + 分页生效）。
5. 点「修改」→ 改文本 → 确定 → 提示"已重新向量化" → 当前页刷新。
6. 去「检索测试」用修改后的关键词检索 → 命中改过的分块（验证向量已更新）。
