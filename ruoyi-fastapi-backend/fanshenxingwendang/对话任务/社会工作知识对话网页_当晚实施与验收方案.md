## 一、项目背景与核心诉求

现有系统基于若依 FastAPI 后端及对应前端，包含通用管理、AI 对话、RAG 知识库和反身性学习业务。反身性研究围绕情境、决策、反思、研究表达等环节展开。

目前需要先交付一个独立入口的知识对话网页，面向高校社会工作教师验收。用户输入问题后，机器人应结合当前会话的历史内容、授权知识库中的教材或文章，以及 LLM 的理解能力，生成有理论依据、可核查的回答。

核心不是“像人一样聊天”，而是：

1. 能理解本轮问题和连续追问中的指代。
2. 能从指定教材、文章中检索相关证据。
3. 能区分原文依据、基于依据的分析和资料不足。
4. 回答明确标注理论依据来自哪本教材、哪篇文章，用户可查看原文。
5. 保留可复用的通用问答能力，不将社会工作业务规则写死在底层 RAG 中。

### 截图的使用边界

参考截图采用左侧助手展示、右侧消息列表、底部输入框、用户和助手气泡区分的形式。本项目借鉴其对话交互，不复用截图中的私人聊天内容、情绪陪伴定位或危机处理话术。

网页建议命名为“社会工作教学与研究助手”。风格专业、清晰、便于阅读长文本；可以沿用紫色强调色，但不要求复制大面积人物形象。左侧优先承载会话和资料范围，给正文与引用留出空间。语音、拟人动画及长期个人记忆不属于今晚范围。

## 四、页面需求

### 页面组成

1. 顶部：助手名称、“基于指定资料回答”的说明、知识库范围。
2. 左侧：新建会话、历史会话；空间足够时展示简短使用说明。
3. 中间：问题与回答消息列表，支持 Markdown、列表和清晰的引用编号。
4. 底部：多行输入、发送按钮、生成中状态；支持 Enter 发送、Shift+Enter 换行。
5. 右侧抽屉或弹层：引用标题、作者、出版/发表信息、章节/页码、原文片段。

建议桌面端优先保证 1440×900 和 1920×1080 可用；较窄屏幕收起侧栏。生成中禁止同一会话重复提交，保留用户输入，错误不显示为成功回答。

### 初始引导问题

- “赋权理论与优势视角有什么联系和区别？”
- “社会工作者如何反思自己在服务关系中的权力位置？”
- “请根据知识库资料解释反身性与一般反思的区别。”

引导问题必须根据实际入库文献调整，不能把无对应资料的问题当作必然能回答的示例。

### 回答组织

优先采用“直接回答 → 理论依据 → 教学/研究场景中的分析 → 限制与来源”的结构，简单问题无需机械分节。正文中的理论论断附引用；应用建议标明属于分析，不包装成教材原话。

## 五、后端处理链路

`身份与会话校验 → 读取当前会话历史 → 补全本轮检索问题 → 过滤授权知识库 → 召回与重排 → 构建编号证据 → LLM 流式回答 → 校验引用编号 → 保存消息与证据快照`

### 关键规则

- 历史消息只读取当前用户有权访问的当前会话，限制轮数与输入预算。
- 对“这个理论”“刚才案例”等追问生成独立检索问题；保留用户原始问题，不用改写覆盖展示文本。
- 不把整段历史直接塞进关键词检索；改写失败时采用可控的原问题回退，必要时请用户澄清。
- 过去的助手回答不是理论证据，不能将模型自己说过的话当作教材依据。
- 每轮重新检查知识库权限及文档有效状态。删除、停用、无权限资料不得进入新回答。
- 检索异常和“未找到相关资料”分别提示，不能一律吞异常返回空结果。
- 资料不充分时允许简短说明不足，不强行给出理论结论。
- 原文是数据，不执行其中可能出现的指令；回答仍服从系统规则。
- 不向日志写 API Key、完整敏感案例或未经脱敏的全部对话。

## 七、数据与引用协议

### 文献元数据（优先扩展现有文档实体）

需要表达：`source_type`（textbook/article/other）、`title`、`authors`、`publication_year`、`edition`、`publisher_or_journal`、`doi_or_url`（可空）。元数据由上传者确认或从可靠资料录入，不能让 LLM 猜测后直接当真。

保留原始文件名，但不能用上传文件名替代正式书名。对于没有书目信息的资料，可显示“上传文档：文件名，作者未录入”，不虚构完整参考文献。

### 回答与证据快照

每条完成的助手消息应能关联：会话 ID、消息 ID、回答文本、生成状态、模型标识、实际使用的引用列表。每条引用至少包含：

```json
{
  "citationId": 1,
  "docId": 20,
  "chunkId": 105,
  "title": "已核验的教材或文章名称",
  "sourceType": "textbook",
  "authors": ["已录入作者"],
  "headingPath": ["第三章", "第二节"],
  "pageLabel": null,
  "locatorType": "section",
  "excerpt": "本次实际提供给模型的原文片段",
  "sourceVersion": "文档版本号或内容摘要"
}
```

示例 ID 和名称仅为协议占位，不是真实文献。引用编号以单条回答为作用域；后端产生编号与映射，模型只能使用提供的编号。

若仅知道 PDF 文件第 N 页，应明确标注“PDF 第 N 页”，不能冒充纸质教材页码。Markdown 无原始页码时展示章节/段落位置。不要伪造精确字符偏移。

引用快照与实际送入模型的片段一致。文档更新后旧回答不错误跳转到新分块；原资料删除或权限撤销后，引用查看按权限及保留策略处理，不因有快照而绕过授权。

## 八、接口与流式事件建议

以下是拟定协议，不表示当前已存在；若现有 API 可复用，则在其上扩展并记录变更。

- 创建会话：`POST /ai/knowledge-chat/sessions`
- 会话列表：`GET /ai/knowledge-chat/sessions`
- 消息历史：`GET /ai/knowledge-chat/sessions/{sessionId}/messages`
- 发送消息：`POST /ai/knowledge-chat/sessions/{sessionId}/messages/stream`
- 查看引用：`GET /ai/knowledge-chat/messages/{messageId}/citations/{citationId}`

发送请求至少包含 `content`、`kbIds`、`clientRequestId`。后端校验长度、会话所有权、知识库范围，并使用请求 ID 防止重复入库。

推荐 POST + fetch 读取 SSE 流，以便携带既有认证信息；不要直接假定原生 EventSource 能发送 POST 或自定义 Authorization。先核对现有 NDJSON/SSE 格式、传输加密中间件与代理缓冲配置，再决定复用或适配。

推荐事件顺序：

1. `meta`：会话与消息标识。
2. `status`：理解问题/检索资料/生成回答。
3. `delta`：回答增量。
4. `citations`：完成校验的引用映射。
5. `done`：本轮生成和持久化完成。
6. 异常时 `error`：可读错误与请求标识，不泄露内部堆栈。

流中显示的引用可先处于待确认状态，以最终校验结果为准。非法引用编号不得渲染为有效来源；应明确提示、修复或将回答标为需核验。编号存在性校验不能替代“原文是否支持论断”的人工验收。

### 回答质量验收

准备固定的 10 个测试问题：4 个理论事实问题、2 个比较问题、2 个依赖上下文的追问、2 个资料不足问题。由用户或社会工作教师预先确认相关片段，不能由同一个生成模型自行判定全部通过。

- 所有展示的引用必须可追溯，伪造书名/作者/页码数量为 0。
- 对有证据的 8 项，至少 7 项回答主旨与证据匹配；其余问题记录并整改，不隐瞒失败。
- 2 项资料不足问题均应明确说明依据不足。
- 引用编号有效率为 100%；逐条人工核对引用是否支持对应论断。
- 这只是小样本演示门槛，不等于生产准确率或学术可靠性保证。

### 体验与工程验收

- 正常网络下，提交后 1 秒内显示本地提交/处理中反馈；这不等于模型首字延迟承诺。
- 记录检索耗时、首字延迟、总耗时和错误率，超时预算由实际模型与部署环境确定并配置。
- 页面长回答可滚动，输入区可用，引用抽屉不遮挡主要操作。
- 新增单测通过，前端生产构建通过；既有失败需列出而不是删除测试。
- “应用路由能装配”与“数据库、存储、模型端到端正常”分别验证。

## 十二、风险与取舍

1. **资料质量先于模型大小**：解析错误、章节丢失、缺少书目信息都会削弱引用质量。
2. **启发式重排只是基线**：权重和阈值需评测，不能将不同 reranker 的分数直接比较。
3. **中文词法召回需实测**：已有候选截断与分词策略可能漏掉相关资料，今晚至少检查演示语料，不宣称全库检索已优化完成。
4. **不要混用向量空间**：不同模型即使维度相同也不能直接混查；切换模型须有重建与版本隔离方案。
5. **涉及真实社会工作案例时先脱敏**：验收优先使用合成案例，不向未确认的外部模型发送可识别服务对象信息。
6. **危机内容不是本次展示重点**：如涉及人身安全，明确专业边界与求助提示，不以教材问答替代紧急干预。
7. **来源显示不等于学术背书**：网页明确“辅助教学与研究，重要结论请核对原文”。
