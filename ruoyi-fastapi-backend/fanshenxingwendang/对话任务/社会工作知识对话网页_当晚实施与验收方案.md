## 一、项目背景与核心诉求

### V1.1 背景修订：先能对话，再用证据增强

验收新增家长交流场景：孩子情绪爆发、询问信息隐私、观察孩子主动整理书籍。仍由高校社会工作教师验收，但助手不能只做教材问答，必须能理解自然交流并连续回应。

核心规则调整为：**对话始终有回应；理论结论有据可查；无据不假装有据。** “回应”包括真实模型答复、澄清或清晰的服务失败提示，不代表所有问题都必须给出专业结论。不得用固定模板冒充 LLM 生成成功。

已选授权知识库但未命中资料时，允许 LLM 基于历史进行一般性回应，标注未找到对应文献依据，不展示伪造引用。明确要求教材证明而资料缺失时仍需说明不足。未选库仍按现有页面规则引导选库，本次不扩展独立无知识库模式。

隐私问题不应由教材检索结果决定：只能根据已核验的存储、访问权限、外部模型传输及保留事实说明，未知则说明无法保证；禁止承诺“绝对保密、外人看不到”。

现有系统基于若依 FastAPI 后端及对应前端，包含通用管理、AI 对话、RAG 知识库和反身性学习业务。反身性研究围绕情境、决策、反思、研究表达等环节展开。

目前需要先交付一个独立入口的知识对话网页，面向高校社会工作教师验收。用户输入问题后，机器人应结合当前会话的历史内容、授权知识库中的教材或文章，以及 LLM 的理解能力，生成有理论依据、可核查的回答。

核心不是“像人一样聊天”，而是：

1. 能理解本轮问题和连续追问中的指代。
2. 能从指定教材、文章中检索相关证据。
3. 能区分原文依据、基于依据的分析和资料不足。
4. 回答明确标注理论依据来自哪本教材、哪篇文章，用户可查看原文。
5. 保留可复用的通用问答能力，不将社会工作业务规则写死在底层 RAG 中。

### 截图的使用边界

参考截图采用左侧助手展示、右侧消息列表、底部输入框、用户和助手气泡区分的形式。本项目借鉴其对话交互，不复用截图中的私人聊天内容、情绪陪伴定位或危机处理话术。

网页建议命名为“社会工作教学与研究助手”。风格专业、清晰、便于阅读长文本；可以沿用紫色强调色，但不要求复制大面积人物形象。左侧优先承载会话和资料范围，给正文与引用留出空间。语音、拟人动画及长期个人记忆不属于今晚范围。

## 四、页面需求

### 页面组成

1. 顶部：助手名称、“专业研讨 / 日常求助”切换、当前模式说明、知识库范围。
2. 左侧：新建会话、历史会话；空间足够时展示简短使用说明。
3. 中间：问题与回答消息列表，支持 Markdown、列表和清晰的引用编号。
4. 底部：多行输入、发送按钮、生成中状态；支持 Enter 发送、Shift+Enter 换行。
5. 右侧抽屉或弹层：引用标题、作者、出版/发表信息、章节/页码、原文片段。

建议桌面端优先保证 1440×900 和 1920×1080 可用；较窄屏幕收起侧栏。生成中禁止同一会话重复提交，保留用户输入，错误不显示为成功回答。

### 初始引导问题

- “赋权理论与优势视角有什么联系和区别？”
- “社会工作者如何反思自己在服务关系中的权力位置？”
- “请根据知识库资料解释反身性与一般反思的区别。”

引导问题必须根据实际入库文献调整，不能把无对应资料的问题当作必然能回答的示例。

### 回答组织

专业研讨优先采用“直接回答 → 理论依据 → 教学/研究场景中的分析 → 限制与来源”的结构，简单问题无需机械分节。日常求助先回应具体处境，提供简短、可执行的支持，必要时追问；不照搬专业分节、不讲授理论名称，依据移至底部折叠区。两种模式都不能把模型应用分析包装成教材原话。

## 五、后端处理链路

`身份与会话校验 → 读取当前会话历史 → 补全本轮检索问题 → 过滤授权知识库 → 召回与重排 → 构建编号证据 → LLM 流式回答 → 校验引用编号 → 保存消息与证据快照`

### 关键规则

- 历史消息只读取当前用户有权访问的当前会话，限制轮数与输入预算。
- 对“这个理论”“刚才案例”等追问生成独立检索问题；保留用户原始问题，不用改写覆盖展示文本。
- 不把整段历史直接塞进关键词检索；改写失败时采用可控的原问题回退，必要时请用户澄清。
- 过去的助手回答不是理论证据，不能将模型自己说过的话当作教材依据。
- 每轮重新检查知识库权限及文档有效状态。删除、停用、无权限资料不得进入新回答。
- 检索异常和“未找到相关资料”分别提示，不能一律吞异常返回空结果。
- 正常检索无命中时，允许基于会话提供一般性支持并说明没有检索到文献依据；专业结论不受资料支持时仍应说明不足。不得一律用固定的“资料不足”文本提前结束自然对话。
- 原文是数据，不执行其中可能出现的指令；回答仍服从系统规则。
- 不向日志写 API Key、完整敏感案例或未经脱敏的全部对话。

## 七、数据与引用协议

### 文献元数据（优先扩展现有文档实体）

需要表达：`source_type`（textbook/article/other）、`title`、`authors`、`publication_year`、`edition`、`publisher_or_journal`、`doi_or_url`（可空）。元数据由上传者确认或从可靠资料录入，不能让 LLM 猜测后直接当真。

保留原始文件名，但不能用上传文件名替代正式书名。对于没有书目信息的资料，可显示“上传文档：文件名，作者未录入”，不虚构完整参考文献。

### 回答与证据快照

每条完成的助手消息应能关联：会话 ID、消息 ID、回答文本、生成状态、模型标识、实际使用的引用列表。每条引用至少包含：

```json
{
  "citationId": 1,
  "docId": 20,
  "chunkId": 105,
  "title": "已核验的教材或文章名称",
  "sourceType": "textbook",
  "authors": ["已录入作者"],
  "headingPath": ["第三章", "第二节"],
  "pageLabel": null,
  "locatorType": "section",
  "excerpt": "本次实际提供给模型的原文片段",
  "sourceVersion": "文档版本号或内容摘要"
}
```

示例 ID 和名称仅为协议占位，不是真实文献。引用编号以单条回答为作用域；后端产生编号与映射，模型只能使用提供的编号。

若仅知道 PDF 文件第 N 页，应明确标注“PDF 第 N 页”，不能冒充纸质教材页码。Markdown 无原始页码时展示章节/段落位置。不要伪造精确字符偏移。

引用快照与实际送入模型的片段一致。文档更新后旧回答不错误跳转到新分块；原资料删除或权限撤销后，引用查看按权限及保留策略处理，不因有快照而绕过授权。

## 八、接口与流式事件建议

以下是拟定协议，不表示当前已存在；若现有 API 可复用，则在其上扩展并记录变更。

- 创建会话：`POST /ai/knowledge-chat/sessions`
- 会话列表：`GET /ai/knowledge-chat/sessions`
- 消息历史：`GET /ai/knowledge-chat/sessions/{sessionId}/messages`
- 发送消息：`POST /ai/knowledge-chat/sessions/{sessionId}/messages/stream`
- 查看引用：`GET /ai/knowledge-chat/messages/{messageId}/citations/{citationId}`

发送请求至少包含 `content`、`kbIds`、`clientRequestId`，V1.2 新增 `answerMode=professional|public`。后端校验模式、长度、会话所有权、知识库范围，并使用请求 ID 防止重复入库；详细合同以 PRD 第 12 节为准。

本次修复采用 POST + fetch 读取当前 NDJSON 流（每行 JSON，type 区分事件），不是标准 event/data SSE 帧。当前响应虽标 text/event-stream，也不能按该媒体类型猜测帧格式。优先修复已有解析器，不单方面迁移协议；同时核对传输加密、代理缓冲及普通 JSON 错误响应。

推荐事件顺序：

1. `meta`：会话与消息标识。
2. `status`：理解问题/检索资料/生成回答。
3. `delta`：回答增量。
4. `citations`：完成校验的引用映射。
5. `done`：本轮生成和持久化完成。
6. 异常时 `error`：可读错误与请求标识，不泄露内部堆栈。

流中显示的引用可先处于待确认状态，以最终校验结果为准。非法引用编号不得渲染为有效来源；应明确提示、修复或将回答标为需核验。编号存在性校验不能替代“原文是否支持论断”的人工验收。

## 十四、V1.1 历史故障与修复方法（保留回归，不假定故障仍存在）

### 14.1 证据与原因

`logs/2026/10/07/error.log` 在 22:53:17、22:54:54 记录 `sqlalchemy.exc.MissingGreenlet`。调用栈指向 `module_ai/service/knowledge_chat_service.py` 的 `stream_answer`，当时第 303 行读取 `session.session_id`。

用户消息提交后，默认 expire_on_commit 使 ORM 对象属性过期；同步访问过期属性触发隐式数据库 IO，在异步调用中报错。因此本次请求在检索和 LLM 调用之前退出，并非已证明模型不可用或知识库无内容。行号可能随改动变化，应按代码语义定位。

另两项代码事实：生成只传当前问题与 context，没有读取历史；无 citations 分支直接返回固定 INSUFFICIENT_TEXT，不调用模型。前端未校验 done/error 终态、静默忽略解析失败、未处理流末尾残留，可能留下空占位。

### 14.2 修复顺序

1. **R01 数据库生命周期**：审查整个函数所有 commit 后读取，包括 session、user_message、assistant_message、citation 序列化。提交前提取必要标量 ID 与响应快照，确需重读时显式 await refresh。不要仅修第 303 行，也不要未经影响分析全局关闭 expire_on_commit。
2. **R02 异常收尾**：覆盖初始化、检索、模型解析/构建、流生成、引用和最终保存。失败时按事务状态 rollback，使用保存的标量定位消息并尽可能提交 failed；流已开始则发 error。不能返回空 completed，不在保存成功前发 done。服务端断开时前端仍需保护。
3. **R03 前端流解析**：兼容当前 NDJSON，处理跨包 UTF-8、末尾 buffer、普通 JSON 错误；解析错误不能静默跳过。EOF 无终态先核对历史，无法确认则显式失败，不自动重调模型。空 finalContent 必须报错，消除空助手气泡。
4. **R04 历史上下文**：读取本人当前会话的有效历史，限制轮数/Token，不重复加入本轮问题。失败消息不进入有效上下文，旧助手回答不作为理论证据，遵守资料撤权规则。
5. **R05 分支策略**：有依据为 grounded；一般支持为 general；要求专业证明但依据不足为 insufficient；需澄清为 clarification。正常零命中与检索异常独立记录，不能统一降级为“没资料”。
6. **R06 真实验收**：使用 PRD 第 11 节三轮输入，检查每轮非空、历史连续、隐私诚实；同时保留 RAG 引用与故障测试。

### 14.3 实施方法与证据要求

- 提交 ORM 过期行为回归测试，需真实模拟默认提交过期，不能只用永不过期的普通对象 Mock 掩盖问题。
- 使用可控测试库和模拟模型覆盖零命中、模型空流、异常、持久化失败；真实模型/资料另做端到端验收。
- 新增 `answerType=general` 时同步 VO、存储枚举/约束（若有）、前端标签、历史序列化和测试。无文献的一般回应为 `citationStatus=not_applicable`、空 citations，不判成 grounded 或 needs_review。
- 增加 `retrievalStatus=matched/no_match/failed/not_attempted`（或等效明确字段），将检索状态与回答类型分开；检索 failed 时若允许继续一般回应，应显示“检索暂不可用，以下不作为文献支持结论”。事务已失败须先安全恢复，不能在失效事务继续生成及保存。
- 真实隐私政策未核验时禁止补写承诺；不为通过测试发送可识别孩子信息，使用下述合成测试输入。
