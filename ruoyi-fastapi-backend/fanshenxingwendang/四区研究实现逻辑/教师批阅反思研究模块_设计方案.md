## 一、需求概述

老师需要按「**班级 / 任务 / 自研课题**」三个维度，查看学生提交的**反思性研究结果**（学习记录），并完成「**AI 先评论 → 老师针对学生结论点评**」的批阅闭环。

- **入口**：教师批阅工作台，可筛选班级、任务、课题类型、学生、批阅状态。
- **批阅内容**：学生的一条学习记录（`edu_learning_record`）对应的反思区成果（按决策分条）+ 四区上下文。
- **AI 评论**：复用 RAG + LLM，对学生反思文本（结合情境/决策/研究上下文）生成结构化评论，落库并可重新生成、保留历史。
- **老师点评**：老师针对学生结论（参考 AI 评论）给出评分 + 评语；点评结果联动同步到 `edu_evaluation` 的反思维度，作为终结性评价的一部分。

> 与现有 `edu_evaluation` 的边界：`edu_evaluation` 是**终结性四区评分**（加权总分 + 优秀标记，把 record 推到 completed）；`edu_review` 是**过程性反思批阅**（AI 评论 + 老师对反思结论的点评文字），发生学生提交后、正式评分前后均可，可反复进行。

### 3.2 各接口详细定义

#### ① GET `/learning/review/records` —— 批阅列表

- **请求参数**（Query，全部可选，`Annotated[ReviewListQueryModel, Query()]`）：

```json
{
  "page_num": 1,
  "page_size": 10,
  "class_id": 103,            // 班级（dept_id），精确
  "task_id": 12,              // 任务/课题 ID，精确
  "creator_type": "0",        // '0'教学任务 / '1'自研课题
  "student_name": "张",        // 学生姓名模糊
  "review_status": "pending", // 'pending'待批阅 / 'commented'已点评 / 'no_ai'未生成AI评论
  "submit_time_begin": "2026-06-01 00:00:00",
  "submit_time_end": "2026-06-30 23:59:59"
}
```

- **响应结构**：

```json
{
  "code": 200,
  "rows": [
    {
      "record_id": 2,
      "task_id": 2,
      "task_name": "张大爷案例行动研究",
      "creator_type": "0",
      "student_id": 5,
      "student_name": "张三",
      "class_id": 103,
      "class_name": "社工21-1班",
      "current_stage": "submitted",
      "status": "submitted",
      "submit_time": "2026-06-15 10:20:00",
      "reflection_status": "2",
      "ai_commented": true,        // 是否已生成 AI 评论
      "ai_comment_version": 2,
      "review_status": "submitted",// null/draft/submitted
      "teacher_comment_brief": "反思深度较好，但…"  // 老师点评摘要（截断）
    }
  ],
  "total": 35,
  "message": "success"
}
```

- **业务逻辑**：
  1. 取教师所管班级：`EduDao.get_teacher_classes(db, current_user.user_id)` → `class_ids`；管理员 `class_ids=None`（不过滤）。
  2. 取所管学生 `user_ids`：`EduDao.get_students_by_class_ids(db, class_ids)`（管理员跳过）。
  3. DAO 查询：`Record × EduTask × StudentUser(SysUser) × EduTaskClass/SysDept`，过滤 `record.user_id IN user_ids`（教师）+ `record.del_flag='0'` + 各筛选条件；自研课题（`creator_type='1'`）的学生通过 `record.user_id` 已覆盖。
  4. LEFT JOIN `edu_review` 拿 `ai_comment_version` / `review_status` / `teacher_comment`（用于 `ai_commented`、`review_status` 列）。
  5. 排序 `submit_time DESC`（未提交的可选不展示或置底）；分页。

#### ② GET `/learning/review/detail/{record_id}` —— 批阅详情

- **响应结构**（聚合，参照 `MonitorService.get_student_detail` 扩展）：

```json
{
  "code": 200,
  "data": {
    "record": { "record_id": 2, "task_id": 2, "task_name": "...", "student_name": "张三", "class_name": "...", "current_stage": "submitted", "status": "submitted", "submit_time": "..." },
    "scenario": { "description": "...", "key_events": [...], "identified_problems": [...] },
    "decisions": [ { "decision_id": 1, "key_event_desc": "...", "action_taken": "...", "reasoning": "...", "ethics_analysis": {...} } ],
    "reflections": [ { "reflection_id": 1, "decision_id": 1, "key_event_desc": "...", "content": "...", "depth_level": "analytical", "depth_score": 0.65, "linked_theories": [...] } ],
    "research": { "selected_question": "...", "framework": {...} },
    "review": {
      "ai_comment": { "summary": "...", "depth_assessment": {...}, "strengths": [...], "weaknesses": [...], "suggestions": [...], "theory_reference": [...], "conclusion": "..." },
      "ai_comment_version": 2,
      "ai_comment_time": "2026-06-15 10:21:00",
      "teacher_comment": "...",
      "overall_comment": "...",
      "reflection_score": 85,
      "ai_comment_feedback": "认同AI评论，补充…",
      "review_status": "submitted",
      "update_time": "..."
    }
  }
}
```

- **业务逻辑**：
  1. **权限校验**（重点）：取 record，校验 `record.user_id ∈ 当前教师所管学生`，否则 `PermissionError('无权查看该学生记录')`。管理员跳过。
  2. 聚合情境/决策/反思/研究（复用 `MonitorService.get_student_detail` 的取数逻辑，反思改用 `ReflectionDao.get_list_by_record_id` 拿**按决策的列表**）。
  3. 取 `edu_review`（按 record_id），解析 `ai_comment` JSONB。

#### ③ POST `/learning/review/ai-comment/{record_id}` —— 生成/重新生成 AI 评论

- **请求参数**（Body，可选）：

```json
{ "scope": "reflection" }   // 'reflection'（仅反思，默认）/ 'full'（含四区）
```

- **响应结构**：

```json
{ "code": 200, "data": { "ai_comment": {...}, "version": 3, "generate_time": "..." } }
```

- **业务逻辑**（复用反思区/伦理分析 AI 模式）：
  1. 权限校验同 ②。
  2. 取 record 关联 task → 拿 `reflection_kb_ids`（AI 评论用反思区知识库）。
  3. **取材料**：反思区所有反思 content（核心）+ 决策 action_taken/reasoning + 情境 key_events（背景）；`scope='full'` 时再加研究区 selected_question。
  4. **RAG 检索**：用学生反思文本做 query，`RetrievalService.hybrid_search(db, query, embedding, reflection_kb_ids, top_k=5)` 检索理论/伦理守则；检索失败降级为空（参照 `decision_service` 容错）。
  5. **构建 Prompt**（见 3.4）→ 用 `ReviewService._resolve_review_model(db, task)` 解析**批阅专用模型**（优先 `task.review_model_id` → 系统默认回落，详见 3.5，**严禁用学生侧 model_id=1**）→ `AiCall.call_llm_json(db, review_model_id, prompt)`。
  6. 解析 JSON（`utils/llm_json_parser.py` 容错）；失败抛 `ValueError('AI评论生成失败，请重试')`。
  7. 落库：写 `edu_review`（upsert，`ai_comment_version += 1`，覆盖最新）+ 写一条 `edu_review_dialogue`（保留历史）。
  8. 区分 `ValueError` 与其他异常，返回友好提示（参照 `decision_controller`）。

#### ④ POST `/learning/review/ai-comment/stream/{record_id}` —— 流式生成（可选）

- 返回 `StreamingResponse(media_type='text/event-stream')`，逐字回显可读内容 + 结束返回结构化结果并落库。实现参照 `reflection_controller.generate_questions_stream`。

#### ⑤ PUT `/learning/review/comment/{record_id}` —— 老师提交/更新点评

- **请求参数**（Body）：

```json
{
  "reflection_score": 85,            // 反思维度评分（0-100），可选
  "teacher_comment": "针对反思结论的点评…",  // 针对反思的点评，必填（提交时）
  "overall_comment": "总评…",         // 可选
  "ai_comment_feedback": "认同AI评论，补充…", // 对 AI 评论的看法，可选
  "submit": true                     // true=提交(review_status='submitted') false=保存草稿('draft')
}
```

- **响应结构**：`{ "code": 200, "data": { "review_id": 1, "review_status": "submitted" } }`

- **业务逻辑**：
  1. 权限校验同 ②。
  2. upsert `edu_review`：写入老师点评字段、`teacher_id`、`review_time`、`review_status`。
  3. **联动 `edu_evaluation`**（保持一致）：若 `edu_review` 已有或本次提交，把 `reflection_score` → `edu_evaluation.reflection_score`，`teacher_comment` → `edu_evaluation.reflection_feedback`（若 evaluation 不存在则不强制创建，仅当 record 已 submitted 才回写）。**不**在此接口改 record.status / 不计算总分（那是 `evaluation/submit` 的职责）。
  4. 校验：`submit=true` 时 `teacher_comment` 不可为空。

#### ⑥ GET `/learning/review/ai-comment-history/{record_id}` —— AI 评论历史

- **响应**：`[{ "version": 1, "ai_comment": {...}, "generate_time": "...", "scope": "reflection" }, ...]`（version DESC）。

### 3.3 业务规则 & 权限控制

| 规则 | 说明 |
|---|---|
| **教师数据范围** | 所有接口统一：`record.user_id ∈ EduDao.get_students_by_class_ids(class_ids)`，`class_ids` 来自 `EduDao.get_teacher_classes(user_id)`；管理员 `class_ids=None` 不过滤。封装为 `ReviewService._check_teacher_permission(db, record, current_user)` 复用 |
| **自动生成 AI 评论** | 学生提交（`record.status` → `submitted`，在 `record_service` 的 submit/advance 钩子）时，用 FastAPI `BackgroundTasks` 异步触发 `ReviewService.generate_ai_comment`，不阻塞学生提交响应；失败仅记日志，不影响提交 |
| **AI 评论可重复生成** | 每次生成 `ai_comment_version += 1`，旧版本进 `edu_review_dialogue`，主表保留最新 |
| **反思区按决策** | 详情页反思数据来自 `edu_reflection_data.decision_id`（已按决策拆分），逐条展示 |
| **与 evaluation 边界** | review 只写反思维度评分/评语，不计算总分、不改 record.status；四区加权总分与 completed 流转仍由 `evaluation/submit` 负责 |
| **只读复用接口权限** | 详情页前端复用 `/learning/reflection/list/{record_id}` 等只读接口，建议后端给这些只读接口同样补教师权限校验（确认 record 属于所管班级学生），避免越权 |

### 3.4 AI 评论 Prompt 设计

**输入材料拼装**（`ReviewService._build_review_context`）：反思文本（逐决策）+ 决策摘要 + 情境关键事件 + （full）研究问题 + RAG 检索到的理论。

**输出 JSON 结构**：

```json
{
  "summary": "对学生反思研究的总体评价（1段）",
  "depth_assessment": {
    "depth_level": "analytical",
    "score": 0.65,
    "comment": "对反思深度达成情况的评价"
  },
  "strengths": ["亮点1", "亮点2"],
  "weaknesses": ["不足1", "不足2"],
  "suggestions": ["改进建议1", "改进建议2"],
  "theory_reference": [
    { "theory_name": "赋权理论", "how_applied": "学生反思中体现/缺失的运用点" }
  ],
  "conclusion": "对学生结论本身的评论（供老师点评参考）"
}
```

Prompt 要点：扮演「社会工作/教育领域资深教师」，基于知识库理论，**评价学生反身性反思的深度与结论的合理性**，指出亮点、不足、改进方向，并给出可被老师采纳的结论评论；JSON 严格按上述结构输出。

### 3.5 批阅（裁判）模型配置 —— 避免「自己既当发牌员又当裁判」

学生侧四区（情境/决策/反思/研究）当前固定用 `model_id=1`。批阅 AI 评论**必须用不同模型**，否则就是模型评价自己（或同模型兄弟）的产出，失去评判意义。

**模型解析优先级**（封装为 `ReviewService._resolve_review_model(db, task) -> int`）：

```
1. task.review_model_id        ← 任务级，老师创建/编辑任务时下拉选择（首选）
2. sys_config: edu.review.default_model_id  ← 系统默认批阅模型（部署时配，必须 ≠ 1）
3. 都缺 → raise ValueError('未配置批阅模型，请联系管理员在任务或系统配置中指定')，不脏生成
```

- **系统默认回落读取**：复用 `module_admin` 的配置服务读 `sys_config` 中 `config_key='edu.review.default_model_id'` 的 `config_value`；部署时由管理员在「参数设置」里配成一个 **≠ 1 且可用** 的模型 ID。
- **同模型告警**（软校验）：解析结果 `== 1`（与学生侧相同）时，记 `logger.warning('[批阅] 裁判模型与学生侧相同(model_id=1)，建议检查任务配置')`，仍允许执行以便排查。
- **审计**：本次评论所用模型写入 `edu_review.review_model_id`，历史表 `edu_review_dialogue.model_id` 同步，便于追溯每次评论由哪个模型生成。

> 说明：本次**不改学生侧**（维持 `model_id=1`）。若未来要让四区各自换模型，再在各 service 把硬编码的 `1` 改为从 task 读取，届时同步校验 `review_model_id != student_model_id`。当前老师只需给任务选一个 ≠1 的裁判模型即可实现隔离。

### 4.2 表关系说明

```
edu_learning_record (1) ──┬── (1) edu_review            [一条学习记录一份批阅]
                          └── (1:N) edu_review_dialogue  [AI评论历史版本]

edu_review.reflection_score / teacher_comment ──联动回写──▶ edu_evaluation.reflection_score / reflection_feedback
```

- `edu_review` 与 `edu_evaluation` 通过 `record_id` 间接关联（均以 record 为单位），不建物理外键，靠业务联动保持一致。
- `student_id`、`task_id` 为冗余字段，避免批阅列表多表 JOIN，加速筛选。

### 4.3 索引建议

- `edu_review(record_id)` UNIQUE —— 按 record 取批阅，高频。
- `edu_review(student_id)` —— 教师按所管学生范围过滤。
- `edu_review(task_id)` —— 按任务筛选。
- `edu_review_dialogue(record_id, version)` —— 历史版本查询。

## 七、风险与注意事项

| # | 风险 | 应对 |
|---|---|---|
| 1 | 现有 `MonitorService.get_class_overview/get_student_detail` **无教师权限校验**，存在越权 | 新批阅模块自带 `_check_teacher_permission`；旧 monitor 接口建议同步补齐（BE-R8） |
| 2 | 学生提交时自动触发 AI 评论耗时 30-60s | 用 `BackgroundTasks` 异步，不阻塞提交；失败仅日志，老师可手动「重新生成」 |
| 3 | LLM 返回 JSON 不规范 | 复用 `llm_json_parser.py` 容错；解析失败返回友好提示，不脏写库 |
| 4 | `model_id=1` 硬编码 | 从 task 配置读取，缺省回落（与反思区现状一致，后续统一改造） |
| 5 | review 与 evaluation 双写一致性 | 点评接口只回写反思维度字段，总分/状态由 evaluation 统一负责；文档明确边界 |
| 6 | 自研课题学生归属判断 | 自研课题 `task.creator_type='1'`，学生通过 `record.user_id` 关联，批阅列表按 `record.user_id ∈ 所管学生` 过滤即可覆盖，无需特殊处理 |
| 7 | **同模型自评（发牌员=裁判）** | 批阅模型解析 `==1`（与学生侧相同）时记 warning；管理员须把 `sys_config: edu.review.default_model_id` 配成 ≠1；老师建任务时选 `review_model_id≠1`。三者都没配则解析报错、不生成 |
