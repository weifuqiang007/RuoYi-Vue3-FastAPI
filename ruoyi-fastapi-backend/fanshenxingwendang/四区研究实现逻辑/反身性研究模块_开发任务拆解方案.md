```sql
CREATE TABLE edu_task (
    task_id          BIGSERIAL PRIMARY KEY,
    task_name        VARCHAR(200) NOT NULL,
    task_description TEXT,
    teacher_id       BIGINT NOT NULL REFERENCES sys_user(user_id),
    -- 教师可指定情境（可选）

    decision_kb_ids  JSONB,

    research_kb_ids  JSONB,

    scenario_config  JSONB,
    reflection_config JSONB,
    deadline         TIMESTAMP,
    status           CHAR(1) DEFAULT '0',   -- 0草稿 1已发布 2已关闭
    del_flag         CHAR(1) DEFAULT '0',
    create_by        VARCHAR(64) DEFAULT '',
    create_time      TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    update_by        VARCHAR(64) DEFAULT '',
    update_time      TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
COMMENT ON TABLE edu_task IS '教学任务表';
CREATE INDEX idx_edu_task_teacher ON edu_task(teacher_id, status);

CREATE TABLE edu_task_class (
    id          BIGSERIAL PRIMARY KEY,
    task_id     BIGINT NOT NULL REFERENCES edu_task(task_id),
    dept_id     BIGINT NOT NULL,
    create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
COMMENT ON TABLE edu_task_class IS '任务-班级分配表';
CREATE INDEX idx_edu_task_class_dept ON edu_task_class(dept_id, task_id);
```

#### 3.1.4 V1.1 修订：支持学生自研课题统一纳入 edu_task 表

> **修订日期**：2026-06-08
> **修订原因**：原设计中学生的"自研课题"通过 `edu_learning_record.task_id=NULL` 实现，导致：(1) 无法统一查询任务列表 (2) 教师无法查看所管班级学生的自研课题 (3) 缺少字段区分任务来源

**核心变更：让 `edu_task` 同时支持教师创建和学生自建**

```
教师指派任务:  edu_task(teacher_id=教师的ID, creator_type='0') → edu_task_class(分配班级)
学生自研课题:  edu_task(teacher_id=NULL, creator_type='1', student_id=学生的ID) → 无班级分配
```

##### 数据库变更（`edu_task` 表，加2个字段 + 修改1个字段）

| 变更类型 | 字段 | 类型 | 说明 |
|---|---|---|---|
| **修改** | `teacher_id` | `BIGINT NOT NULL` → `BIGINT`（去掉 NOT NULL） | 学生创建时为 NULL |
| **新增** | `creator_type` | `CHAR(1) DEFAULT '0'` | `'0'`=教师创建，`'1'`=学生自建 |
| **新增** | `student_id` | `BIGINT NULL` | 学生创建时记录学生 user_id，教师创建时为 NULL |

对应 SQL：

```sql
-- 修改 teacher_id 为可空
ALTER TABLE edu_task ALTER COLUMN teacher_id DROP NOT NULL;

-- 新增 creator_type 字段
ALTER TABLE edu_task ADD COLUMN creator_type CHAR(1) DEFAULT '0';
COMMENT ON COLUMN edu_task.creator_type IS '创建者类型（0教师创建 1学生自建）';

-- 新增 student_id 字段
ALTER TABLE edu_task ADD COLUMN student_id BIGINT;
COMMENT ON COLUMN edu_task.student_id IS '学生创建者ID，关联sys_user.user_id，教师创建时为NULL';

-- 新增索引：按学生查询自研课题
CREATE INDEX idx_edu_task_student ON edu_task(student_id) WHERE creator_type = '1';
```

> `edu_task_class`、`edu_learning_record` 及其他表 **无需变更**。

##### 查询逻辑变更

| 角色 | 看到什么 | 查询逻辑 |
|---|---|---|
| **教师** | 自己创建的任务 + 所管班级学生的自研课题 | `WHERE (creator_type='0' AND teacher_id=?) OR (creator_type='1' AND student_id IN (该教师所管班级的学生ID列表))` |
| **学生** | 教师指派到本班级的任务 + 自己创建的自研课题 | 指派任务走 `edu_task_class` 关联；自研走 `WHERE creator_type='1' AND student_id=?` |
| **管理员** | 全部 | 无过滤 |

> 教师查看所管班级学生：通过 `edu_teacher_class` → 获取教师绑定的班级 → 通过 `edu_student_profile.class_id` → 获取班级内所有学生 ID

##### 后端变更清单

| 文件 | 变更点 |

```sql
CREATE TABLE edu_learning_record (
    record_id        BIGSERIAL PRIMARY KEY,
    task_id          BIGINT REFERENCES edu_task(task_id),  -- 可为NULL（自研课题）
    user_id          BIGINT NOT NULL REFERENCES sys_user(user_id),  -- V1.2修订：原student_id改为user_id，支持所有角色
    -- 当前阶段：scenario/decision/reflection/research/submitted/completed
    current_stage    VARCHAR(20) DEFAULT 'scenario',
    -- 各区完成状态：0未开始 1进行中 2已完成
    scenario_status  CHAR(1) DEFAULT '0',
    decision_status  CHAR(1) DEFAULT '0',
    reflection_status CHAR(1) DEFAULT '0',
    research_status  CHAR(1) DEFAULT '0',
    -- 各区数据ID（方便快速查找）
    scenario_id      BIGINT,
    decision_id      BIGINT,
    reflection_id    BIGINT,
    research_id      BIGINT,
    -- 整体状态
    status           VARCHAR(20) DEFAULT 'ongoing',
    score            DECIMAL(5,2),
    teacher_feedback TEXT,
    start_time       TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    submit_time      TIMESTAMP,
    complete_time    TIMESTAMP,
    del_flag         CHAR(1) DEFAULT '0',
    create_by        VARCHAR(64) DEFAULT '',
    create_time      TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    update_by        VARCHAR(64) DEFAULT '',
    update_time      TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(task_id, user_id)
);
COMMENT ON TABLE edu_learning_record IS '学习记录主表（四区联动主控）';
CREATE INDEX idx_record_user ON edu_learning_record(user_id);
CREATE INDEX idx_record_task ON edu_learning_record(task_id);
```

## 九、关键设计决策

### 9.1 自研课题处理

- 学生可以在没有教师指派任务的情况下，自主新增反身性研究
- 实现：`edu_learning_record.task_id` 为 NULL
- 学生任务列表同时展示：教师指派的任务（有task_id）和自研课题（task_id=NULL）
- 自研课题不设deadline，可随时编辑

### 9.2 四区模板统一

- 无论是教师指派、自研课题、还是查看历史记录，前端四区使用同一套页面模板
- 区别仅在于：有预设情境的任务，情境区会预填教师指定的情境内容
- 通过 `record_id` 作为路由参数，加载对应的数据

### 9.3 AI调用统一模式

所有四区的AI调用遵循统一模式：

```python
async def zone_ai_call(zone_data, task):
    # 1. 从 task 配置拿知识库 ID
    kb_ids = task.xxx_kb_ids
    # 2. RAG 检索
    embedding = await EmbeddingService.embed_single(用户输入)
    chunks = await RetrievalService.hybrid_search(db, 用户输入, embedding, kb_ids, top_k=5)
    # 3. 构建 Prompt
    prompt = PROMPT_TEMPLATE.format(retrieved_knowledge=format(chunks), ...)
    # 4. 调用 LLM
    result = await AiCall.call_llm_json(query_db, model_id, prompt)
    return result
```

### 9.4 防抖策略

- 反思区深度评估：保存后30秒内不重复调用LLM评估
- 前端自动保存：每30秒或失焦时触发保存

## 十一、风险与应对

| 风险 | 影响 | 应对措施 |
|---|---|---|
| LLM返回JSON格式不稳定 | 解析失败 | 已有 `llm_json_parser.py` 兼容处理 |
| RAG检索不相关 | AI回答质量差 | 各区独立配置知识库ID，提高检索精准度 |
| 反思区深度评估不准确 | 引导方向偏 | Prompt精心设计 + 教师可自定义reflection_config |
| 学生频繁保存触发大量LLM调用 | 成本高、响应慢 | 30秒防抖策略 |
| 前端四区状态同步复杂 | 数据不一致 | 通过 record 主表状态机控制，前端不缓存中间状态 |
