# V1.1 修订方案：edu_task 表支持学生自研课题（前后端+数据库全量变更）

> 修订日期：2026-06-08
> 修订原因：原设计 `teacher_id NOT NULL`，仅教师可创建任务。学生自研课题通过 `learning_record.task_id=NULL` 临时实现，导致双数据源、查询复杂、教师无法监控学生自研。
> 修订方案：统一 `edu_task` 表同时支持教师创建和学生自建，废弃 `task_id=NULL` 临时方案。

---

## 一、数据库变更（已完成 — ruoyi-fastapi-pg.sql 末尾已追加）

以下 SQL 已追加在 `sql/ruoyi-fastapi-pg.sql` 文件末尾（第 1349~1375 行），需要在 PostgreSQL 中执行：

```sql
-- 1. teacher_id 改为可空（学生创建时没有教师关联）
ALTER TABLE edu_task ALTER COLUMN teacher_id DROP NOT NULL;
COMMENT ON COLUMN edu_task.teacher_id IS '创建任务的教师用户ID，关联sys_user.user_id；学生自研课题时为NULL';

-- 2. 新增 creator_type 字段：区分任务来源
--    '0' = 教师创建的教学任务（原有逻辑不变）
--    '1' = 学生自己创建的自研课题
ALTER TABLE edu_task ADD COLUMN creator_type CHAR(1) DEFAULT '0';
COMMENT ON COLUMN edu_task.creator_type IS '创建者类型（0教师创建的教学任务 1学生自己创建的自研课题）';

-- 3. 新增 student_id 字段：学生创建时记录是哪个学生
--    教师创建时为 NULL，学生创建时填写学生的 user_id
--    用于：教师查看所管班级学生的自研课题列表
ALTER TABLE edu_task ADD COLUMN student_id BIGINT;
COMMENT ON COLUMN edu_task.student_id IS '学生创建者ID，关联sys_user.user_id；教师创建时为NULL，学生自研时填写自己的用户ID';

-- 4. 新增索引：按学生ID快速查询自研课题（条件索引，只索引学生创建的记录）
CREATE INDEX idx_edu_task_student ON edu_task(student_id) WHERE creator_type = '1';
COMMENT ON INDEX idx_edu_task_student IS '按学生ID索引自研课题，仅索引creator_type=1的记录';
```

### 字段含义汇总

| 字段名 | 类型 | 变更类型 | 含义 |
|--------|------|---------|------|
| `teacher_id` | BIGINT NULL | 修改（非空→可空） | 创建任务的教师用户ID。教师创建时有值，学生自研课题时为 NULL |
| `creator_type` | CHAR(1) DEFAULT '0' | **新增** | 创建者类型。`'0'`=教师创建的教学任务，`'1'`=学生自己创建的自研课题 |
| `student_id` | BIGINT NULL | **新增** | 学生创建者ID。教师创建时为 NULL，学生自研时填写自己的 user_id |

## 二、后端代码变更（已完成）

### 2.1 task_do.py（实体类）
- `teacher_id`：`nullable=False` → `nullable=True`
- 新增字段：`creator_type = Column(CHAR(1), server_default='0')`
- 新增字段：`student_id = Column(BigInteger, nullable=True)`

### 2.2 task_vo.py（视图模型）
- `TaskVO` 新增字段：`creator_type: Optional[str] = '0'`、`student_id: Optional[int] = None`、`teacher_id` 改为 `Optional[int]`
- 新增模型 `StudentTaskCreateModel`：学生自建课题请求体，仅需 `task_name` + `task_description`

### 2.3 task_dao.py（数据访问层）
- `get_published_tasks_by_dept_ids`：增加 `creator_type == '0'` 过滤，排除学生自研课题
- 新增 `get_student_self_tasks(student_id)`：查询学生自己的自研课题
- 新增 `get_teacher_all_tasks(teacher_id, class_ids)`：教师视角，查自己创建的 + 所管班级学生的自研课题

### 2.4 task_service.py（服务层）
- `create_task`：创建时显式设置 `creator_type='0'`
- 新增 `create_student_task`：学生自建课题，`creator_type='1'`，`status='1'`（直接发布）
- `update_task`/`delete_task`：权限校验兼容双类型（教师改自己的任务 / 学生改自己的课题）
- `get_teacher_tasks`：改为查询教师自己任务 + 所管班级学生自研课题（合并展示）
- `get_student_tasks`：废弃旧的 `RecordDao.get_self_study_records` 双数据源方案，统一从 `edu_task` 表查询
- `_task_to_dict`：返回值新增 `creator_type`、`student_id` 字段

### 2.5 task_controller.py（控制器）
- 新增接口 `POST /learning/task/student/create`：学生自建自研课题
- `/list` 接口：返回数据现在包含所管班级学生的自研课题
- `/update`、`/delete` 接口：权限校验已兼容教师/学生双角色

## 三、前端工程师变更清单（待前端实施）

### ⚠️ 本次修改的核心变更点

**一句话总结**：任务列表接口的返回数据新增了 `creator_type` 和 `student_id` 字段，同时新增了一个学生自建课题的接口。前端需要根据这些字段做展示区分。

---

### 变更点 1：任务列表响应数据新增字段

**影响接口**：
- `GET /learning/task/list`（教师任务列表）
- `GET /learning/task/student/list`（学生任务列表）
- `GET /learning/task/detail/{task_id}`（任务详情）

**新增返回字段**：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `creator_type` | string | `'0'`=教师创建的教学任务，`'1'`=学生自建的自研课题 |
| `student_id` | int or null | 学生创建者的用户ID，教师创建时为 null |
| `teacher_id` | int or null | **类型变化**：原来一定有值，现在学生自研课题时为 null |

**前端需要做什么**：
1. 任务列表表格中，根据 `creator_type` 字段显示不同的标签/标记：
   - `creator_type === '0'` → 显示标签「教学任务」（蓝色）
   - `creator_type === '1'` → 显示标签「自研课题」（绿色）
2. 如果教师任务列表需要区分来源，可以增加一列「来源」，显示「教师创建」或「学生自研」
3. 任务详情页中，如果 `teacher_id` 为 null，不要显示教师相关信息

---

### 变更点 2：新增学生自建课题接口

**新接口**：
- **URL**: `POST /learning/task/student/create`
- **请求体**：
  ```json
  {
    "task_name": "我的自研课题名称",
    "task_description": "课题描述（可选）"
  }
  ```
- **响应**：
  ```json
  {
    "code": 200,
    "data": { "task_id": 123 }
  }
  ```

**前端需要做什么**：
1. 在学生的「我的任务」页面（对应菜单 4100），增加一个「新建自研课题」按钮
2. 点击按钮弹出对话框，表单包含：
   - 课题名称（必填，最大 200 字）
   - 课题描述（选填，文本域）
3. 提交时调用 `POST /learning/task/student/create`
4. 成功后刷新任务列表，新课题会出现在列表中（`source='self_study'`，`creator_type='1'`）

---

### 变更点 3：教师任务列表现在包含学生自研课题

**影响接口**：`GET /learning/task/list`

**变更说明**：
- 原来只返回教师自己创建的任务
- 现在还会返回教师所管班级学生创建的自研课题
- 可通过 `creator_type` 字段区分

**前端需要做什么**：
1. 教师任务列表中，如果 `creator_type === '1'`（学生自研课题）：
   - 可以用不同的样式/颜色标记
   - 可以显示「学生: xxx」标签（后端后续可追加学生姓名，目前有 student_id）
2. 可以增加一个筛选下拉框，选项为「全部 / 教学任务 / 学生自研」，前端按 `creator_type` 过滤

---

### 变更点 4：学生任务列表数据结构变化

**影响接口**：`GET /learning/task/student/list`

**变更说明**：
- 原来自研课题返回时 `task_id` 为 `null`、`task_name` 固定为「自研课题」
- 现在自研课题也有正常的 `task_id` 和真实的 `task_name`
- `source` 字段仍保留：`'assigned'`=教师指派，`'self_study'`=学生自研
- 新增 `creator_type` 和 `student_id` 字段

**前端需要做什么**：
1. 原来用 `record_id` 来区分自研课题的逻辑需要调整，现在用 `source === 'self_study'` 或 `creator_type === '1'` 来判断
2. 自研课题点击进入时，现在有正常的 `task_id`，用 `task_id` 跳转到正常的学习流程（不再需要 special case）
3. **废弃旧逻辑**：原来 `task_id === null` 判断自研课题的代码可以移除

# V1.2 修订方案：edu_learning_record 表 student_id → user_id 重命名

> 修订日期：2026-06-10
> 修订原因：阶段2学习记录原设计仅面向学生（`student_id`），V1.2已支持所有角色（student/teacher/admin）创建学习记录，字段名 `student_id` 语义不准确，统一改为 `user_id`。
> 修订范围：数据库列重命名 + 后端 ORM/DAO/Service/VO + 前端监控页面 + API 返回字段名。

---

## 一、数据库变更

```sql
-- edu_learning_record 表：student_id → user_id
ALTER TABLE public.edu_learning_record RENAME COLUMN student_id TO user_id;
COMMENT ON COLUMN public.edu_learning_record.user_id IS '用户ID，关联sys_user.user_id（支持student/teacher/admin所有角色）';

-- 唯一约束和索引自动跟随列名，无需额外操作
```

## 二、后端代码变更

### 2.1 record_do.py（实体类）
- `student_id = Column(...)` → `user_id = Column(...)`，comment 更新为"记录所属用户ID（支持student/teacher/admin）"

### 2.2 record_vo.py（视图模型）
- `student_id: int` → `user_id: int`

### 2.3 record_dao.py（数据访问层）
- `EduLearningRecord.student_id` → `EduLearningRecord.user_id`（所有查询条件）
- 方法名 `get_by_task_and_student` → `get_by_task_and_user`

### 2.4 record_service.py（服务层）
- 所有方法参数 `student_id` → `user_id`
- `record.student_id` → `record.user_id`（ORM 属性访问）
- `_record_to_dict` 返回字段 `'student_id'` → `'user_id'`
- `start_task` 新增 `roles` 参数，预留角色扩展

### 2.5 record_controller.py（控制器）
- 所有接口 summary 标注"所有角色可用"
- `start_task` 传递 `current_user.roles` 给 service

### 2.6 evaluation_service.py（评价服务）
- `r.student_id` / `record.student_id` → `r.user_id` / `record.user_id`
- 返回字段 `'student_id'` → `'user_id'`

## 三、前端代码变更

| 文件 | 变更 |
|---|---|
| `views/learning/monitor/ClassOverview.vue` | `prop="student_id"` → `prop="user_id"`，label "学生ID" → "用户ID" |
| `views/learning/monitor/EvaluationForm.vue` | `prop="student_id"` → `prop="user_id"`，label "学生ID" → "用户ID" |

## 四、不受影响的文件

以下文件中的 `student_id` 属于其他表（edu_task / edu_scenario_data / edu_decision_data / edu_reflection_data / edu_research_data），**不需要修改**：
- `task_do.py`、`task_dao.py`、`task_service.py`、`task_vo.py`
- `scenario_do.py`、`scenario_vo.py`、`scenario_service.py`
- `decision_do.py`、`decision_vo.py`、`decision_service.py`
- `reflection_do.py`、`reflection_vo.py`、`reflection_service.py`
- `research_do.py`、`research_vo.py`、`research_service.py`
- 前端 `StudentTaskList.vue`、`TeacherTaskManager.vue`（使用的是 edu_task 的 student_id）
