# 线上部署手册：打包上传与版本更新流程

> 本文档记录「研修班知识管理系统」（RuoYi-Vue3-FastAPI）从 Windows 本机打包 → 上传服务器 → 启动运行的完整流程。
>
> **主要用途**：以后每次发新版本，按「[五、日常版本更新流程](#五日常版本更新流程)」执行即可；首次部署或服务器重置时，按全文从头走一遍。
>
> 全程**不使用 git**，采用「本地打包 → 上传 → 服务器 docker 构建」的方式。

## 二、整体架构

```
用户浏览器 ──http://115.220.6.150:15348──▶ 宿主机 nginx(:15348)
                                            │
                                 ┌──────────┴────────────┐
                          前端 dist 静态文件        /prod-api/* 反代
                          (/mnt/zhangyichi/web/dist)     │
                                                    (剥掉 /prod-api 前缀)
                                                          │
                                                          ▼
                                       后端容器 ruoyi-backend
                                       (容器:9099 → 宿主机:15349)
                                                          │
                              ┌─────────────┬─────────────┴──────────┐
                         postgres:15432  redis:21348            minio:29000
                        （服务器已跑的容器，后端通过 host.docker.internal 访问）
```

**关键链路要点**：
- 前端打包前缀 `/prod-api`（来自 `.env.production` 的 `VITE_APP_BASE_API`）。
- nginx 把 `/prod-api/xxx` **剥掉前缀**后转成 `/xxx` 给后端（后端是裸路由）。
- 后端容器通过 `host.docker.internal` 访问宿主机上的 postgres/redis/minio（不走公网回环，避免防火墙和安全问题）。

## 四、首次部署完整流程

### 第 1 步：Windows 本机打包

**① 前端打包**（在 `ruoyi-fastapi-frontend` 目录）：
```bash
npm run build:prod
# 产物在 dist/，把它打包
tar -czf web-dist.tar.gz -C dist .
```

**② 后端打包**（在 `G:\zhangyichi` 目录，源码打包，要带上 Dockerfile.prod / .env.prod）：
```bash
tar -czf backend.tar.gz \
  --exclude=ruoyi-fastapi-backend/__pycache__ \
  --exclude=ruoyi-fastapi-backend/build \
  --exclude=ruoyi-fastapi-backend/logs \
  --exclude=ruoyi-fastapi-backend/.pytest_cache \
  --exclude=ruoyi-fastapi-backend/.idea \
  --exclude=ruoyi-fastapi-backend/tests \
  ruoyi-fastapi-backend
```
得到 `web-dist.tar.gz` 与 `backend.tar.gz` 两个包。

### 第 2 步：上传到服务器

用 WinSCP / scp / FileZilla 把两个包传到服务器 `/mnt/zhangyichi/`。

### 第 3 步：服务器 — 解压部署

```bash
cd /mnt/zhangyichi
mkdir -p web/dist

# 解压后端
tar -xzf backend.tar.gz
mv ruoyi-fastapi-backend backend      # 若已存在先备份再覆盖

# 解压前端
tar -xzf web-dist.tar.gz -C web/dist

# 确认部署文件齐全
ls /mnt/zhangyichi/backend/Dockerfile.prod /mnt/zhangyichi/backend/.env.prod
```

### 第 4 步：服务器 — 构建并启动后端容器

```bash
cd /mnt/zhangyichi/backend

# 构建镜像（首次装 AI 依赖较慢，约 5~15 分钟）
docker build -f Dockerfile.prod -t ruoyi-backend:prod .

# 启动容器
docker run -d --name ruoyi-backend \
  -p 15349:9099 \
  --add-host=host.docker.internal:host-gateway \
  -v /mnt/zhangyichi/backend/logs:/app/logs \
  --restart unless-stopped \
  ruoyi-backend:prod

# 看启动日志，确认无报错（出现 "Uvicorn running on http://0.0.0.0:9099" 即成功，Ctrl+C 退出查看不会停容器）
docker logs -f ruoyi-backend
```

### 第 5 步：服务器 — 配置 nginx

编辑 `/usr/local/nginx/conf/nginx.conf`，在 `http { ... }` 内追加（完整内容见 [附录 A.4](#a4-nginx-server-block)）：

```nginx
    # ========== 研修班知识管理系统（前端 :15348 / 后端反代 :15349）==========
    server {
        listen       15348;
        server_name  _;

        location / {
            root   /mnt/zhangyichi/web/dist;
            index  index.html index.htm;
            try_files $uri $uri/ /index.html;
            client_max_body_size 1024M;
        }

        location /prod-api/ {
            proxy_pass http://localhost:15349/;   # ⚠️ 末尾必须带 /，剥掉 /prod-api 前缀
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;

            proxy_http_version 1.1;
            proxy_set_header Connection "";
            proxy_buffering off;          # SSE 流式输出必须关
            proxy_read_timeout 600s;
            proxy_send_timeout 600s;
            client_max_body_size 1024M;
        }
    }
```

重载：
```bash
cp /usr/local/nginx/conf/nginx.conf /usr/local/nginx/conf/nginx.conf.bak
/usr/local/nginx/sbin/nginx -t && /usr/local/nginx/sbin/nginx -s reload
```

### 第 6 步：放行端口

```bash
firewall-cmd --permanent --add-port=15348/tcp && firewall-cmd --reload
# ⚠️ 云服务器还要去云控制台「安全组」放行 15348/tcp
```

### 第 7 步：验证

```bash
# ① 后端直连（绕过 nginx），返回含 uuid/img 的 JSON 即正常
curl -i http://127.0.0.1:15349/captchaImage

# ② 经 nginx，同样应返回 JSON（验证前缀剥离生效）
curl -i http://127.0.0.1:15348/prod-api/captchaImage
```
浏览器打开 **http://115.220.6.150:15348**，看到登录页并能登录即全链路通。

## 五、日常版本更新流程

> **这是以后最高频的操作。** 改了代码后，按「前端更新」「后端更新」分别执行。两者互不影响，可单独进行。

### 5.1 只更新前端

1. Windows（`ruoyi-fastapi-frontend` 目录）：
   ```bash
   npm run build:prod
   tar -czf web-dist.tar.gz -C dist .
   ```
2. 上传 `web-dist.tar.gz` 到服务器 `/mnt/zhangyichi/`。
3. 服务器替换静态文件：
   ```bash
   cd /mnt/zhangyichi
   rm -rf web/dist/* && tar -xzf web-dist.tar.gz -C web/dist
   # 静态文件直接生效，nginx 一般无需重启；保险起见可 reload
   /usr/local/nginx/sbin/nginx -s reload
   ```
4. 浏览器 **Ctrl+F5 强制刷新**（清缓存）。

### 5.2 只更新后端

1. Windows（`G:\zhangyichi` 目录）打包后端（命令同 [第 1 步 ②](#第-1-步windows-本机打包)）：
   ```bash
   tar -czf backend.tar.gz \
     --exclude=ruoyi-fastapi-backend/__pycache__ \
     --exclude=ruoyi-fastapi-backend/build \
     --exclude=ruoyi-fastapi-backend/logs \
     --exclude=ruoyi-fastapi-backend/.pytest_cache \
     --exclude=ruoyi-fastapi-backend/.idea \
     --exclude=ruoyi-fastapi-backend/tests \
     ruoyi-fastapi-backend
   ```
2. 上传 `backend.tar.gz` 到服务器 `/mnt/zhangyichi/`。
3. 服务器替换源码 + 重建镜像 + 重启容器：
   ```bash
   cd /mnt/zhangyichi
   # 备份旧目录（保险，可省略）
   mv backend backend.bak.$(date +%s) 2>/dev/null
   tar -xzf backend.tar.gz && mv ruoyi-fastapi-backend backend

   cd backend
   # 重建镜像（依赖没变时 docker 会用缓存，主要重跑 pip install . 和 COPY，较快）
   docker build -f Dockerfile.prod -t ruoyi-backend:prod .

   # 停删旧容器，启动新容器
   docker rm -f ruoyi-backend
   docker run -d --name ruoyi-backend \
     -p 15349:9099 \
     --add-host=host.docker.internal:host-gateway \
     -v /mnt/zhangyichi/backend/logs:/app/logs \
     --restart unless-stopped \
     ruoyi-backend:prod

   # 确认启动正常
   docker logs -f ruoyi-backend
   ```
4. 验证：`curl -i http://127.0.0.1:15349/captchaImage` 返回 JSON 即可。

> 💡 **若只改了 Python 代码、没动 `requirements-pg.txt`**，第 3 步 `docker build` 会命中缓存，几十秒就完成。若改了依赖，会重新安装，慢一些。

### 5.3 前后端都更新

先做 5.1，再做 5.2（或反过来），互不干扰。

## 六、常见错误排查（踩坑记录）

> 以下是首次部署时实际踩过的坑，**务必逐条遵守**，否则会重复踩。

### 6.1 ⭐ 接口 404：`/prod-api/captchaImage` Not Found
**根因**：后端是**裸路由**（`/captchaImage`），`APP_ROOT_PATH=/prod-api` 只是 Swagger 文档的元数据，不会自动给路由加前缀。nginx 必须把 `/prod-api` 前缀**剥掉**再转给后端。

**修复**：nginx 的 `proxy_pass` **末尾必须带 `/`**：
```nginx
location /prod-api/ {
    proxy_pass http://localhost:15349/;   # ✅ 末尾带 /，剥前缀
    # proxy_pass http://localhost:15349;  # ❌ 末尾空，会保留 /prod-api 前缀 → 后端 404
}
```
- 诊断方法：`curl -i http://127.0.0.1:15349/captchaImage`（裸路径直连后端）返回 200 → 后端正常，是 nginx 没剥前缀。
- 浏览器 F12 → Network 看 `captchaImage` 的请求 URL 应该是**一层** `/prod-api/captchaImage`（不是两层）。

### 6.2 后端连不上数据库 / Redis / MinIO
**根因**：`.env.prod` 里 host 不能写公网 IP（`115.220.6.150`），容器内访问公网回环到宿主机会被防火墙卡，且暴露数据库端口不安全。

**修复**：host 用 `host.docker.internal`，启动加 `--add-host=host.docker.internal:host-gateway`（容器内特指宿主机）：
```
DB_HOST = 'host.docker.internal'
REDIS_HOST = 'host.docker.internal'
MINIO_HOST = 'host.docker.internal:29000'
```
- 前提：Docker **≥ 20.10**（支持 host-gateway）。先 `docker version` 确认。
- 若 Docker 版本过低不支持 host-gateway → 三处 host 改成 `172.17.0.1`（默认 bridge 网关）。

### 6.3 容器启动报 `ruoyi: command not found`
**根因**：`ruoyi` 命令由 `pyproject.toml` 的 `[project.scripts]` 注册，**必须 `pip install .` 安装项目本体**才有。原 `Dockerfile.pg` 只装了 requirements，漏了这步。

**修复**：`Dockerfile.prod` 里必须有：
```dockerfile
COPY . .
RUN pip install --no-cache-dir . -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 6.4 刷新前端页面 404（子路由）
**根因**：Vue Router 是 history 模式，刷新子路由时 nginx 找不到对应文件。
**修复**：前端 location 必须有 `try_files $uri $uri/ /index.html;`。

### 6.5 AI 流式生成卡住 / 不逐字输出
**根因**：nginx 默认缓冲代理响应，SSE 流被攒着一起返回。
**修复**：后端反代 location 必须有 `proxy_buffering off;`。

### 6.6 文件/资料上传报 413 Request Entity Too Large
**修复**：两个 location 都加 `client_max_body_size 1024M;`。

### 6.7 登录报错、接口数据异常（库是空的）
**根因**：postgres 的 `ruoyi-fastapi` 库没有表结构/初始数据。
**修复**：把后端 `sql/` 目录下的初始化脚本导进 postgres。

### 6.8 镜像构建慢 / 失败
- 慢是正常的（首次装 litellm/anthropic 等一堆 AI SDK，5~15 分钟）。
- 若 pip 失败，确认服务器能访问 `https://pypi.tuna.tsinghua.edu.cn/simple`（清华镜像）。
