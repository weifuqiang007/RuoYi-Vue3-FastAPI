> **版本**：V1.0
> **日期**：2026-06-11
> **编写人**：后端架构师
> **基于文档**：`决策区_决策记录交互改造需求.md`（前端 AI 生成）

---

## 一、需求回顾

前端提出 3 个改造点：

| # | 需求 | 核心诉求 |
|---|---|---|
| 1 | 页面首次进入时，自动回填"最近更新"的一条决策记录到表单 | 不要每次进来都是空白表单 |
| 2 | 列表去掉 ID 列，改为"点选当前决策"（单选框/行点击） | 同一事件多种决策时，明确"当前编辑的是哪一条" |
| 3 | 每条记录的操作列增加"删除"按钮 | 可以删除不需要的决策 |

---

## 二、架构决策

### 2.1 "当前决策"是否需要后端持久化？

**结论：方案 A — 仅前端选择态，不需要后端持久化。**

理由：
- "当前选中哪条决策"纯粹是前端 UI 交互状态，用户在同一个页面内切换即可
- 不存在"跨设备记住选中状态"的业务需求
- 用户进入四区工作台时，默认选中"最近更新"的那条即可，这个逻辑前端拿 `update_time DESC` 排序的列表第一条就能实现
- **不新增数据库字段，不改表结构**

### 2.2 "最近更新"的判断依据

**结论：以 `update_time` 为准，`update_time` 为空时回退到 `create_time`。**

理由：
- 数据库表中已有 `update_time` 字段（每次 save 都会更新）
- DAO 的 `get_by_record_id` 查询当前按 `key_event_index` 排序，需改为 `update_time DESC`
- 前端取列表第一条就是最近更新的记录

### 2.3 删除规则

| 规则 | 决定 |
|---|---|
| 删除方式 | **逻辑删除**（`del_flag = '2'`），和项目其他模块一致 |
| 谁能删 | **只能删自己的**（`student_id = 当前用户`） |
| 什么时候能删 | 决策区**未确认**时可删（`record.decision_status != '2'`）；已确认后禁止删除 |
| 删完后的联动 | 前端处理：如果删的是当前选中的，自动切到剩余中最近更新的那条；全删完则显示空白表单 |

## 三、后端改造方案

### 3.1 改造清单

| 序号 | 改造内容 | 涉及文件 | 改动量 |
|---|---|---|---|
| 1 | DAO 排序改为 `update_time DESC` | `decision_dao.py` | 1 行 |
| 2 | Service `get_list` 返回数据增加 `update_time` 字段 | `decision_service.py` | 2 行 |
| 3 | 新增删除接口（DAO / Service / Controller） | 三个文件 | 约 20 行 |

### 3.2 详细说明

#### 改动 1：DAO 排序调整

**文件**：`module_learning/dao/decision_dao.py`

**当前**（按 `key_event_index` 排序）：
```python
.order_by(EduDecisionData.key_event_index)
```

**改为**（按 `update_time DESC`，最近更新的排最前）：
```python
.order_by(desc(EduDecisionData.update_time))
```

同时加上 `del_flag = '0'` 过滤（当前查询缺少此条件）：
```python
.where(EduDecisionData.record_id == record_id, EduDecisionData.del_flag == '0')
```

> 前端拿到的列表第一条就是最近更新的决策，直接回填即可。

#### 改动 2：`get_list` 增加 `update_time` 字段

**文件**：`module_learning/service/decision_service.py` 的 `get_list` 方法

在返回字典中增加：
```python
'update_time': str(d.update_time) if d.update_time else None,
'create_time': str(d.create_time) if d.create_time else None,
```

> 当前 `get_list` 返回的数据里没有 `update_time`，前端无法判断哪条是最近更新的。加上后前端可以据此排序列表，也可以直接取第一条。

#### 改动 3：新增删除接口

**文件**：`decision_dao.py` / `decision_service.py` / `decision_controller.py`

**DAO 层** — 新增 `delete` 方法（逻辑删除）：
```python
@classmethod
async def delete(cls, db: AsyncSession, decision_id: int) -> None:
    from sqlalchemy import update
    await db.execute(
        update(EduDecisionData)
        .where(EduDecisionData.decision_id == decision_id)
        .values(del_flag='2')
    )
```

**Service 层** — 新增 `delete` 方法（含权限校验和状态校验）：
```python
@classmethod
async def delete(cls, db: AsyncSession, decision_id: int, user_id: int) -> dict:
    decision = await DecisionDao.get_by_id(db, decision_id)
    if not decision or decision.del_flag == '2':
        raise ValueError('决策记录不存在')
    # 权限校验：只能删自己的
    if decision.student_id != user_id:
        raise PermissionError('无权删除他人的决策记录')
    # 状态校验：检查学习记录的决策区是否已完成
    record = await RecordDao.get_by_id(db, decision.record_id)
    if record and record.decision_status == '2':
        raise ValueError('决策区已确认，无法删除决策记录')
    # 逻辑删除
    await DecisionDao.delete(db, decision_id)
    return {'decision_id': decision_id}
```

**Controller 层** — 新增删除路由：
```python
@staticmethod
@decision_controller.delete('/delete/{decision_id}', summary='删除决策记录')
async def delete_decision(
    request: Request,
    decision_id: int,
    query_db: Annotated[AsyncSession, DBSessionDependency()],
    current_user: Annotated[CurrentUserModel, CurrentUserDependency()],
) -> Response:
    try:
        result = await DecisionService.delete(query_db, decision_id, current_user.user.user_id)
        return ResponseUtil.success(data=result)
    except (ValueError, PermissionError) as e:
        return ResponseUtil.failure(msg=str(e))
```

**新增接口信息**：

| 项目 | 内容 |
|---|---|
| **URL** | `DELETE /learning/decision/delete/{decision_id}` |
| **权限** | student / teacher / admin |
| **入参** | `decision_id`（路径参数） |
| **出参** | `{"decision_id": 12}` |
| **错误码** | 400：记录不存在 / 无权删除 / 决策区已确认 |

### 4.2 初始化逻辑

```
进入决策区
  ↓
loadDecisionList()   // 调用 GET /learning/decision/list/{record_id}
  ↓
列表是否为空？
  ├─ 是 → newDecision()  // 空白表单
  └─ 否 → 列表第一条（后端已按 update_time DESC 排序） → 回填表单 + 标记为选中
```

关键代码逻辑（伪代码）：
```javascript
async function initDecision() {
  const list = await getDecisionList(recordId)
  if (list.length > 0) {
    // 后端已按 update_time DESC 排序，第一条就是最近的
    currentDecision.value = list[0]
    selectedDecisionId.value = list[0].decision_id
    fillForm(list[0])
  } else {
    newDecision()
  }
}
```

### 4.4 删除交互

```javascript
async function handleDelete(row) {
  await ElMessageBox.confirm('确定删除该决策记录？', '提示', { type: 'warning' })
  await deleteDecision(row.decision_id)
  // 刷新列表
  await loadDecisionList()
  // 如果删的是当前选中的
  if (row.decision_id === selectedDecisionId.value) {
    const list = decisionList.value
    if (list.length > 0) {
      // 自动选中剩余中最近更新的（列表已排序，取第一条）
      selectDecision(list[0])
    } else {
      newDecision()  // 空白表单
    }
  }
}
```

## 六、测试用例

### 用例1：列表排序验证

```bash
curl -X GET "http://localhost:8088/learning/decision/list/1" \
  -H "Authorization: Bearer <token>"
```

**预期**：
- 返回数据按 `update_time` 降序排列（最近更新的在最前）
- 每条记录包含 `update_time` 和 `create_time` 字段

### 用例2：删除决策记录

```bash
curl -X DELETE "http://localhost:8088/learning/decision/delete/1" \
  -H "Authorization: Bearer <token>"
```

**预期**：返回 `{"decision_id": 1}`，数据库中 `del_flag` 变为 `'2'`

### 用例3：删除他人记录（权限校验）

用用户 B 的 token 删除用户 A 的决策记录：

```bash
curl -X DELETE "http://localhost:8088/learning/decision/delete/1" \
  -H "Authorization: Bearer <用户B_token>"
```

**预期**：返回错误 `{"msg": "无权删除他人的决策记录"}`

### 用例4：决策区已确认后删除（状态校验）

```bash
# 决策区已确认（decision_status='2'）后再删除
curl -X DELETE "http://localhost:8088/learning/decision/delete/1" \
  -H "Authorization: Bearer <token>"
```

**预期**：返回错误 `{"msg": "决策区已确认，无法删除决策记录"}`

```bash
curl -X DELETE "http://localhost:8088/learning/decision/delete/9999" \
  -H "Authorization: Bearer <token>"
```

**预期**：返回错误 `{"msg": "决策记录不存在"}`
