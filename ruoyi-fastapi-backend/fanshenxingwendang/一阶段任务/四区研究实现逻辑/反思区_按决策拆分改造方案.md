# 反思区按决策拆分改造方案

> **文档版本**：v1.5
> **编写日期**：2026-06-13
> **修订原因**：反思区与决策区数据粒度不匹配，反思应从 record 级别（1:1）改为 decision 级别（1:N）

---

## 一、改造背景

### 现状

```
edu_learning_record (1)
  ├── edu_scenario_data (1) → key_events[] JSONB（多个关键事件）
  ├── edu_decision_data (N) → 每个关键事件一条决策记录
  └── edu_reflection_data (1) → 整条 record 只有一条反思
```

### 问题

1. 决策区按关键事件做了 1:N 拆分，但反思区仍是 1:1。AI Prompt 中 `_get_decision_summary()` 将所有决策揉成模糊摘要，无法针对具体关键事件给出精准理论指导
2. 无法独立评估学生在不同关键事件上的反思深度
3. 数据链路断裂：scenario → decision（细粒度）→ reflection（粗粒度）

### 目标

```
edu_learning_record (1)
  ├── edu_scenario_data (1) → key_events[] JSONB
  ├── edu_decision_data (N) → 每个关键事件一条决策
  └── edu_reflection_data (N) → 每个决策对应一条反思（1:1 with decision）
```

---

## 二、数据库变更

```sql
-- edu_reflection_data 新增 decision_id 字段
ALTER TABLE edu_reflection_data ADD COLUMN decision_id BIGINT;
COMMENT ON COLUMN edu_reflection_data.decision_id IS '关联的决策记录ID，每个决策对应一条独立反思，关联edu_decision_data.decision_id';

-- 新增索引：按决策查询反思
CREATE INDEX idx_reflection_decision ON edu_reflection_data(decision_id);

-- record_id 保留，方便按 record 查询所有反思
```

## 三、后端改造清单

### 3.1 DO 层 — `entity/do/reflection_do.py`

- `EduReflectionData` 新增字段：
  ```python
  decision_id = Column(BigInteger, comment='关联的决策记录ID，每个决策对应一条独立反思，关联edu_decision_data.decision_id')
  ```

### 3.2 VO 层 — `entity/vo/reflection_vo.py`

- `ReflectionSaveModel`：
  - 新增 `decision_id: int = Field(..., description='关联的决策记录ID')`
  - `record_id` 保留，但改为可选（后端从 decision 中反查 record_id）
- `ReflectionVO`：
  - 新增 `decision_id`, `key_event_desc` 字段

### 3.3 DAO 层 — `dao/reflection_dao.py`

- 新增 `get_by_decision_id(db, decision_id) -> EduReflectionData | None`
- `get_by_record_id` 改为 `get_list_by_record_id(db, record_id) -> list`（返回列表）

### 3.4 Service 层 — `service/reflection_service.py`

| 方法 | 变更内容 |
|---|---|
| `save()` | 接收 `decision_id`，按 `decision_id` 查找或创建反思；从 decision 反查 `record_id` |
| `generate_questions()` | Prompt 中 `_get_decision_summary()` 改为 `_get_decision_context(decision_id)`，注入单条决策的完整上下文 |
| `confirm()` | 校验 record 下所有决策是否都有反思内容 |
| `get_detail()` | 改为 `get_by_decision(decision_id)`，返回单条决策的反思详情 |
| 新增 `get_list_by_record(record_id)` | 返回 record 下所有反思列表 |
| `REFLECTION_PROMPT` | `{decision_summary}` → `{decision_context}` |
| 新增 `_get_decision_context()` | 返回单条决策的完整上下文（key_event_desc + action_taken + reasoning + ethics_analysis） |

### 3.5 Controller 层 — `controller/reflection_controller.py`

| 接口 | 变更 |
|---|---|
| `POST/PUT /save` | 入参新增 `decision_id` |
| `POST /questions` | 不变（仍用 `reflection_id`） |
| `GET /detail/{record_id}` | → `GET /list/{record_id}`（返回所有反思列表） |
| 新增 `GET /detail-by-decision/{decision_id}` | 返回单个决策的反思详情 |
| `PUT /confirm` | 不变（仍用 `record_id`） |
| `GET /depth/{reflection_id}` | 不变 |
| `GET /depth-history/{reflection_id}` | 不变 |

## 四、前端改造清单

### 4.1 API 层 — `api/learning/reflection.js`

- `saveReflection` 入参新增 `decision_id`
- 新增 `getReflectionList(recordId)` 替代 `getReflectionDetail`
- 新增 `getReflectionByDecision(decisionId)` 获取单条
- `generateReflectionQuestions` 不变

### 4.2 主页面 — `views/learning/reflection/index.vue`

核心改造：从"单个编辑器"变为"按关键事件分 Tab"

- 页面加载时先调 `getDecisionList(recordId)` 获取决策列表，再调 `getReflectionList(recordId)` 获取反思列表
- 用 `el-tabs` 展示，每个 Tab 对应一个决策/关键事件
- Tab 标签：`关键事件 N：{key_event_desc 简短版}`
- 底部聚合展示：深度折线图 + 理论总览 + 确认按钮
- 确认按钮校验所有关键事件都有反思内容

### 4.3 新增组件 — `components/DecisionReflectionTab.vue`

每个 Tab 的内容组件，封装：
- 反思编辑器 textarea
- 保存按钮 + 生成理论指导按钮
- AI 理论指导展示（theory_guidance + direction + questions）
- 深度指示器
- Props: `decisionId`, `keyEventDesc`, `recordId`, `reflectionData`

## 五、Prompt 改造详情

### 改前（模糊摘要）

```
关键决策：
- 节点「张大爷情绪失控」：介入，安抚情绪
- 节点「家属拒绝配合」：未介入，...
```

### 改后（精准上下文）

```
当前关键事件：张大爷情绪失控
你的决策：介入，采取安抚措施
你的理由：认为老人的情绪需要被理解和接纳
心理状态：紧张但坚定
AI伦理分析摘要：涉及自决权与保护性干预的张力...
请针对这一具体决策进行反身性反思
```
