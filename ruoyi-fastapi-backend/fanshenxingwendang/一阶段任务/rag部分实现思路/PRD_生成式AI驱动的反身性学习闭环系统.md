## 一、项目概述

### 1.1 项目背景

在《社会工作行动研究》课程教学中，传统教学模式面临两大核心困境：

1. **"实践场"的缺失**：课堂难以模拟连续、真实、有责任压力的实践情境，学生反思流于表层，无法实现"行动者反身性"所要求的在行动中建构意义的能力。
2. **"研究思考"的悬置**：学生难以在"计划-行动-观察-反思"的完整循环中获得高频、个性化的过程性指导，其"研究问题"多依赖教师预设，而非从自身实践困境中内生演化而来。

### 1.2 产品定位

本产品是一个面向高等教育社会工作专业的**情境化智能教学平台**，通过生成式AI技术构建"情境进入—问题生成—行动决策—反身性反思—研究表达"的完整学习闭环，支持学生从实践体验中生成研究问题与学术成果。

### 1.3 产品目标

| 目标层次 | 具体目标 |
|---|---|
| 能力闭环目标 | 构建持续运行的"行动-反思-生成"学习闭环，打通反身性能力养成的关键断点 |
| 课程转型目标 | 推动《社会工作行动研究》从"方法讲授"中心向"过程生成"中心转型 |
| 技术示范目标 | 形成"生成式AI作为学习支架赋能能力生成"的文科教学创新模式，可迁移至同类课程 |

## 三、核心功能模块设计

### 3.0 知识库管理模块（基础设施层）

> **定位**：本模块是所有教学活动的基石，为四区联动提供专业知识检索支撑。

#### 3.0.1 功能描述

将社会工作课件、教材、学术论文、案例资料等专业文献，通过RAG（检索增强生成）技术转化为可被AI检索和引用的结构化知识。

#### 3.0.2 知识入库流程

```
原始文档（PDF/Word/TXT/网页）
    ↓
文档解析（提取正文、表格、图片说明）
    ↓
智能分块（按段落/章节/语义切分为500-1000字的文本块）
    ↓
向量化（bge-large-zh模型将文本块编码为向量）
    ↓
存储（文本块 + 向量 + 元数据 → Milvus向量数据库）
```

#### 3.0.3 知识检索流程

```
用户提问/场景描述
    ↓
问题向量化（同一Embedding模型）
    ↓
相似度检索（Milvus中召回Top-K相关文本块）
    ↓
重排序（可选：Cross-Encoder精排）
    ↓
将检索结果注入大模型Prompt → 生成回答
```

#### 3.0.4 知识来源规划

| 来源类型 | 示例 | 入库方式 |
|---|---|---|
| 教师课件 | PPT/PDF格式课件 | 手动上传，系统自动解析 |
| 专业教材 | 《社会工作导论》《质性研究方法》等 | 手动上传PDF |
| 学术论文 | CNKI/万方下载的社会工作行动研究论文 | 批量导入PDF |
| 案例库 | 已整理的"情境-决策-反思"结构化案例（JSON） | 按模板批量导入 |
| 开放知识 | 社会工作伦理守则、政策法规等 | 网页采集或手动录入 |
| 学生生成内容 | 历届优秀反思日志、研究框架（经脱敏） | 系统内沉淀 |

### 3.1 情境区（Scenario Zone）

> **核心功能**：学生描述实践场景，系统辅助识别和界定关键问题。

#### 3.1.1 功能描述

学生在实习/实践中遇到的真实情境，通过文字描述（或录音转文字）输入系统。系统基于社会工作专业知识库，辅助学生：

- **识别情境中的关键事件和行动节点**
- **界定其中蕴含的专业问题**
- **判断问题所属的社会工作实践领域**（如医务社工、社区社工、老年社工等）

#### 3.1.2 学生操作界面要素

| 界面元素 | 说明 |
|---|---|
| 场景描述编辑器 | 富文本编辑区，学生在此撰写实践场景描述（建议300-800字） |
| AI辅助提问按钮 | 点击后AI基于已有描述追问关键细节（如：当事人的情绪状态、你的角色定位等） |
| 问题识别面板 | AI自动从描述中提取2-3个潜在问题，学生选择或修改 |
| 关键节点标注 | 学生在描述文本中高亮标注关键事件节点（如"大爷情绪失控"） |
| 场景分类标签 | 系统自动推荐+学生确认的场景类别标签 |

#### 3.1.3 AI核心能力

```
输入：学生的场景描述文本
处理：
  1. RAG检索相关知识（相似案例、社会工作理论）
  2. 大模型分析：提取关键事件、识别专业问题、推荐理论视角
输出：
  - 问题界定报告（含问题摘要、涉及的专业领域、相关理论）
  - 追问建议（引导学生补充缺失的关键信息）
  - 相似历史案例推荐
```

#### 3.1.4 示例交互

**学生输入**：
> 社区张大爷在服务过程中发现他因为有经济困难，然后拒绝与人沟通。导致社工与其沟通过程中发生口角，情绪失控。

**AI输出**：
> **识别到以下关键事件节点**：
> 1. 张大爷因经济困难而自我封闭
> 2. 社工与张大爷沟通中发生口角
> 3. 张大爷情绪失控
>
> **潜在的专业问题**：
> 1. **服务对象阻抗问题**：如何理解服务对象的拒绝沟通行为背后的心理动因？
> 2. **专业关系建立困境**：社工在面对服务对象情绪爆发时，应如何调整介入策略？
> 3. **伦理决策问题**：服务对象情绪失控时，是否应强行介入？介入的边界在哪里？
>
> **建议追问**：
> - 你当时的角色是什么？（一线社工/实习生/督导）
> - 在口角发生前，你与张大爷的沟通方式是怎样的？
> - 你是否了解张大爷经济困难的具体原因和程度？

### 3.2 决策区（Decision Zone）

> **核心功能**：学生在关键节点做出行动决策，阐述理由，形成伦理决策记录。

#### 3.2.1 功能描述

基于情境区识别出的关键问题，学生在本区域进行伦理决策分析。系统引导学生：

- **回顾关键事件节点**
- **分析可选的行动方案及其伦理依据**
- **记录自身的选择、行动和心理活动**
- **参照社会工作伦理守则进行决策评估**

#### 3.2.2 学生操作界面要素

| 界面元素 | 说明 |
|---|---|
| 关键节点时间线 | 以时间轴展示情境区标注的关键事件节点 |
| 决策记录表 | 结构化表单，记录每个关键节点的决策分析 |
| 伦理参照面板 | 自动检索并展示相关的社会工作伦理守则条款 |
| 历史方案参考 | 展示相似案例中其他同学或专家的处理方案（匿名化） |
| 决策对比视图 | 并排展示不同决策路径的可能后果（AI辅助分析） |

#### 3.2.3 决策记录结构

每位学生在每个关键节点需填写以下结构化信息：

```
决策记录表
├── 关键节点：________________（从情境区关联）
├── 节点描述：________________（自动带入）
├── 我是否介入：□ 是  □ 否  □ 部分介入
├── 我的具体行动：________________
├── 我选择该行动的理由：________________
├── 当时的心理活动和感受：________________
├── 我考虑的替代方案：________________
├── 我预期的结果：________________
├── 实际发生的结果（事后补充）：________________
└── 伦理冲突识别：________________（AI辅助提示）
```

#### 3.2.4 AI核心能力

```
输入：学生的决策记录 + 情境描述
处理：
  1. RAG检索社会工作伦理守则相关条款
  2. 检索相似历史案例中的决策参考
  3. 大模型分析：识别伦理冲突、评估决策合理性、提出替代视角
输出：
  - 伦理冲突提示（如"自决权 vs 保护义务"）
  - 相关伦理条款引用
  - 替代决策方案建议
  - 历史案例中类似决策的参考
```

#### 3.2.5 示例交互

**学生填写决策记录**：
> 关键节点：大爷情绪失控，是否要强行介入？
> 我是否介入：是
> 我的具体行动：我试图安抚大爷的情绪，并建议他去社区服务中心坐下来谈
> 我选择该行动的理由：我觉得不能放任大爷的情绪不管，可能会有更严重的后果
> 当时的心理活动：很紧张，怕大爷出事，也怕自己处理不当

**AI输出**：
> **伦理维度分析**：
>
> 你的决策涉及以下伦理维度：
> 1. **服务对象自决权**（NASW伦理守则1.02）：服务对象有权自主决定是否接受服务。强行介入是否尊重了张大爷的自决权？
> 2. **保护义务**：当服务对象可能因情绪失控而伤害自身时，社工有保护义务。你的介入动机具有伦理正当性。
>
> **理论视角参考**：
> - **生态系统理论**：张大爷的自我封闭可能与经济压力、社区支持网络薄弱等环境因素有关
> - **危机干预理论**：情绪失控情境下，优先稳定情绪、确保安全是正确的第一反应
>
> **建议进一步思考**：
> - 如果张大爷拒绝你的建议，你会怎么做？
> - 你在介入过程中是否注意到了自己的情绪反应对决策的影响？

### 3.3 反思区（Reflection Zone）

> **核心功能**：AI基于专业知识进行结构化提问，引导学生从"描述经历"转向"反身性反思"。

#### 3.3.1 功能描述

这是本系统的**核心创新模块**。反思区通过AI驱动的结构化提问，实现三个层次的反身性引导：

1. **描述性反思**：帮助学生完整叙述事件经过和自身反应
2. **分析性反思**：引导学生分析自身与情境的互动，理解行为背后的假设
3. **反身性反思**：促使学生审视自身立场、价值观对实践的影响，实现"研究者反身性"

#### 3.3.2 学生操作界面要素

| 界面元素 | 说明 |
|---|---|
| 反思日志编辑器 | 大型富文本编辑区，支持分步引导式撰写 |
| AI提问引导栏 | 在编辑器侧边展示AI推送的结构化问题链 |
| 知识关联面板 | 自动展示与当前反思相关的社会工作理论和社会学概念 |
| 思维演变追踪 | 可视化展示学生多轮反思中的思维变化轨迹 |
| 反思深度指示器 | 实时评估当前反思文本所处的反思层次（描述/分析/反身性） |

#### 3.3.3 AI结构化提问策略

AI的提问遵循递进式引导策略，通过问题链推动反思深化：

```
第一层：描述性提问（还原事件）
  → "当时张大爷说了什么？你的第一反应是什么？"
  → "你注意到情境中有哪些细节？"

第二层：分析性提问（理解互动）
  → "你认为张大爷拒绝沟通的背后可能有什么原因？"
  → "你的紧张情绪是否影响了你的沟通方式？"
  → "在这个互动中，你的角色期望是什么？"

第三层：反身性提问（审视自身）
  → "你的介入决策是否受到了你自身价值观的影响？"
  → "如果你是张大爷，你希望社工如何对待你？"
  → "这次经历如何改变了你对'专业帮助'的理解？"
  → "你在多大程度上将自己的生活经验带入了对这个情境的判断？"

第四层：理论连接提问（知识整合）
  → "你所描述的这种现象，与社会学中的XX理论有什么关联？"
  → "从XX视角来看，你如何重新理解这个情境？"
```

#### 3.3.4 AI核心能力

```
输入：学生的反思文本 + 情境描述 + 决策记录
处理：
  1. 分析当前反思文本的深度层次
  2. RAG检索相关的社会工作理论、社会学概念
  3. 检索学生历史反思记录，识别思维演变轨迹
  4. 大模型生成：个性化问题链、理论关联建议、反思深度提升引导
输出：
  - 针对性的追问问题（基于当前反思层次动态调整）
  - 关联的专业理论概念和依据
  - 相似案例中其他同学的反思参考（匿名化）
  - 反思深度评估与提升建议
```

#### 3.3.5 示例交互

**学生反思文本**：
> 我觉得这次经历让我意识到社工不是简单地"帮助"别人。张大爷的拒绝其实也是一种权利表达。我以前总觉得帮助别人是好事，但现在觉得"好意"可能也是一种控制。

**AI输出**：
> **反思深度评估**：你的反思已经进入"反身性反思"层次，触及了自身价值观对实践的审视。
>
> **进一步追问**：
>
> 1. 你提到"'好意'可能也是一种控制"——这是一个非常有洞察力的观察。你能否追溯一下，这种认识是在哪个瞬间产生的？是在张大爷拒绝你的时候，还是事后反思时才意识到的？
>
> 2. 你说"社工不是简单地帮助别人"——那么你认为社工的"帮助"和普通人理解的"帮助"有什么本质区别？
>
> **理论关联**：
>
> 你的反思触及了以下专业理论：
>
> - **赋权理论（Empowerment Theory）**：你意识到服务对象的"拒绝"是一种权利表达，这与Solomon提出的赋权视角高度一致——赋权的第一步是承认服务对象的主体性。
>
> - **反压迫实践（Anti-oppressive Practice）**：你反思"好意可能是控制"，这呼应了Dominelli关于社会工作实践中隐性权力关系的讨论。社会工作者需要持续审视自身的权力位置。

### 3.4 研究生成区（Research Generation Zone）

> **核心功能**：帮助学生将实践材料和反思成果转化为研究问题、论文框架和研究初稿。

#### 3.4.1 功能描述

在前三个区域积累的情境描述、决策记录和反思成果基础上，AI辅助学生：

- **从实践材料中凝练研究问题**
- **构建论文框架和逻辑线**
- **推荐相关文献和理论支撑**
- **辅助撰写论文初稿段落**

#### 3.4.2 学生操作界面要素

| 界面元素 | 说明 |
|---|---|
| 材料汇总面板 | 自动汇总前三个区域的全部产出材料 |
| 研究问题生成器 | AI基于材料生成候选研究问题，学生选择和修改 |
| 论文框架编辑器 | 可视化的论文大纲编辑器（拖拽排序） |
| 文献推荐列表 | AI推荐的相关文献和理论资源 |
| 论文撰写编辑器 | 分章节的论文撰写环境，AI可辅助生成段落建议 |
| 逻辑检查工具 | AI检查论文各部分之间的逻辑连贯性 |

#### 3.4.3 研究生成流程

```
Step 1：材料汇总
  自动提取情境描述 + 决策记录 + 反思日志中的关键素材
    ↓
Step 2：研究问题凝练
  AI分析材料中的核心矛盾和理论线索，生成3-5个候选研究问题
  示例输出：
    "社会工作者在服务对象阻抗情境中的伦理决策过程研究——基于反身性视角"
    "从'好意的控制'到'赋权式陪伴'：一线社工与服务对象互动中的反身性实践研究"
    ↓
Step 3：论文框架构建
  AI基于选定的研究问题，生成论文大纲建议
  示例框架：
    1. 绪论（研究背景、问题提出、研究意义）
    2. 文献综述（反身性理论、社会工作伦理决策、服务对象阻抗）
    3. 研究方法（行动研究方法论、自我民族志、反思日志分析）
    4. 研究发现（情境再现、决策分析、反身性洞察）
    5. 讨论（理论对话、实践启示）
    6. 结论
    ↓
Step 4：分章节辅助撰写
  AI基于前期材料，为每个章节提供段落建议和写作支架
  学生在每个章节中调用自己的实践材料和反思内容
    ↓
Step 5：逻辑审查与润色
  AI检查论文的逻辑连贯性、学术规范性
  提供学术语言润色建议
```

#### 3.4.4 AI核心能力

```
输入：全部学习过程数据（情境+决策+反思）+ 研究方向选择
处理：
  1. 分析材料中的核心主题、矛盾和理论线索
  2. RAG检索相关学术文献、理论框架
  3. 大模型生成：研究问题、论文框架、段落建议、文献推荐
输出：
  - 候选研究问题列表（含理论依据）
  - 论文框架（可编辑的大纲结构）
  - 各章节写作支架和段落建议
  - 推荐文献列表（含摘要和关联说明）
  - 学术语言润色建议
```

### 5.4 RAG知识库技术方案

#### 5.4.1 文档处理Pipeline

```
原始文档
    ↓
[Parsing Engine] 文档解析
    ├── PDF → PyMuPDF / pdfplumber 提取正文
    ├── Word → python-docx 提取正文
    ├── PPT → python-pptx 提取文本
    └── TXT → 直接读取
    ↓
[Cleaning Engine] 文本清洗
    ├── 去除无关格式标记
    ├── 修复编码问题
    ├── 识别并保留专业术语
    └── 标记文档结构（标题、段落、列表）
    ↓
[Chunking Engine] 智能分块
    ├── 策略1：按段落分块（基础）
    ├── 策略2：按语义边界分块（推荐）
    │   → 使用语义相似度判断分块边界
    ├── 策略3：按文档结构分块（标题+内容）
    └── 块大小：500-1000字，重叠100字
    ↓
[Embedding Engine] 向量化
    ├── 模型：bge-large-zh-v1.5
    ├── 维度：1024
    └── 批量处理，存入Milvus
    ↓
[Index Engine] 索引构建
    ├── Milvus IVF_FLAT 索引
    └── 元数据过滤支持（按来源类型、关键词等）
```

#### 5.4.2 检索增强策略

```
用户输入（提问/场景描述/反思文本）
    ↓
[Query Processing] 查询处理
    ├── 查询扩展：大模型将用户输入改写为多个检索查询
    ├── 关键词提取：提取社会工作专业术语
    └── 元数据过滤：限定检索范围（如仅检索论文类）
    ↓
[Retrieval] 混合检索
    ├── 向量相似度检索（Milvus Top-20）
    ├── 关键词检索（BM25 Top-20）
    └── 合并去重
    ↓
[Reranking] 重排序
    ├── Cross-Encoder精排（bge-reranker-large）
    └── 取Top-5最相关文本块
    ↓
[Prompt Construction] Prompt构建
    ├── 系统提示词（角色设定+任务指令）
    ├── 检索到的知识片段（标注来源）
    └── 用户输入内容
    ↓
[Generation] 大模型生成
    └── 调用大模型API，流式返回结果
```

### 5.5 大模型调用方案

#### 5.5.1 模型选型策略

采用**可插拔模型架构**，通过统一的LLM Service接口封装，支持灵活切换底层模型：

| 用途 | 推荐模型 | 备选模型 | 说明 |
|---|---|---|---|
| 通用对话与分析 | DeepSeek-V3 API | 智谱GLM-4-Plus | 性价比优，中文能力强 |
| Embedding | bge-large-zh-v1.5（本地部署） | 智谱Embedding-3 API | 向量化模型，本地部署无API费用 |
| 长文本处理 | DeepSeek API（128K上下文） | 通义千问-Long | 处理长篇反思日志和论文 |

#### 5.5.2 Prompt工程设计

每个区域配置独立的Prompt模板，支持教师自定义调整：

**情境区Prompt模板（示例）**：
```
系统角色：你是一位经验丰富的社会工作督导，擅长帮助实习社工分析实践情境。

任务：根据学生描述的实践场景，完成以下工作：
1. 识别场景中的关键事件节点
2. 界定其中蕴含的专业问题（2-3个）
3. 判断问题所属的社会工作实践领域
4. 提出追问建议，帮助学生补充关键信息

专业知识参考：
{retrieved_knowledge}

学生场景描述：
{student_scenario}

请以专业但易于理解的语气回复，避免使用过多学术术语。
```

**反思区Prompt模板（示例）**：
```
系统角色：你是一位引导反思的社会工作教育者，擅长通过提问帮助学生从"描述经历"走向"反身性反思"。

当前反思层次评估规则：
- 描述性：仅复述事件经过和个人感受
- 分析性：开始分析事件原因、互动模式、策略选择
- 反身性：审视自身价值观、立场、权力关系对实践的影响

任务：
1. 评估学生当前反思所处的层次
2. 基于当前层次，生成2-3个推动反思深化的追问
3. 关联相关的社会工作理论或社会学概念
4. 提供理论依据说明为什么这种关联成立

专业知识参考：
{retrieved_knowledge}

学生反思文本：
{reflection_text}

历史反思记录（思维演变追踪）：
{reflection_history}

请确保追问具有针对性，不要泛泛而谈。每个追问都要有明确的目标——推动学生进入更深一层的反思。
```

## 六、数据安全与合规设计

### 6.1 数据安全措施

| 安全维度 | 具体措施 |
|---|---|
| **数据传输** | 全站HTTPS加密传输 |
| **数据存储** | 敏感数据加密存储，数据库访问控制 |
| **学生隐私** | 学生反思内容脱敏处理，案例共享时匿名化 |
| **数据隔离** | 班级间数据隔离，学生只能查看自己的数据 |
| **访问控制** | 基于角色的访问控制（RBAC） |
| **数据备份** | 自动定期备份，支持灾难恢复 |

### 6.2 AI合规要求

| 合规要求 | 落实措施 |
|---|---|
| **使用国内模型** | 全部使用国内大模型API（DeepSeek/智谱/通义），数据不出境 |
| **内容审查** | AI生成内容标注"AI生成"标识，教师审核后呈现给学生 |
| **学术诚信** | AI辅助内容明确标注辅助性质，学生需独立完成核心决策和反思 |
| **数据脱敏** | 学生反思文本在上传大模型前进行姓名等敏感信息脱敏 |

## 九、总结

本系统以"情境区—决策区—反思区—研究生成区"四区联动为核心架构，通过RAG知识库为AI提供社会工作专业知识支撑，以精心设计的Prompt工程实现各区域的智能化引导，最终构建"连续行动—动态反思—研究生成"的反身性学习闭环。

系统的技术创新在于：

1. **将AI从信息工具重塑为"智能学习支架"**，精准介入反思深度和研究表达这两个最难突破的环节
2. **四区联动设计**实现了"做-思-写"的同步与融合
3. **RAG知识库**确保AI的引导基于真实的社会工作专业知识，而非通用知识的泛泛而谈
4. **可插拔的模型架构**保障技术方案的灵活性和可持续性

本技术方案可为后续的系统开发提供完整的技术实施指导。
