# 接口变更文档：学习记录列表 - 返回课题信息 + 新增查询条件

> **版本**：V1.0
> **日期**：2026-06-11
> **变更人**：后端

---

## 一、接口信息

| 项目 | 内容 |
|---|---|
| **接口URL** | `GET /learning/record/my` |
| **接口名称** | 我的学习记录列表 |
| **权限** | student / teacher / admin |
| **变更类型** | 入参变更（新增查询参数） + 出参变更（新增课题关联字段） |

---

## 二、变更内容

### 2.1 入参变更

**变更前**：接口只支持 `page_num` 和 `page_size`，无过滤条件。

**变更后**：新增 6 个可选查询参数，使用 Pydantic `RecordListQueryModel` 自动解析：

| 参数名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `creator_type` | string | 否 | 创建者类型筛选：`'0'`=教师创建的教学任务，`'1'`=学生自建课题 |
| `task_name` | string | 否 | 课题名称（模糊匹配，ilike） |
| `create_time_begin` | string | 否 | 创建时间范围起始，如 `2026-06-01` |
| `create_time_end` | string | 否 | 创建时间范围结束，如 `2026-06-30` |
| `deadline_begin` | string | 否 | 截止时间范围起始，如 `2026-06-01` |
| `deadline_end` | string | 否 | 截止时间范围结束，如 `2026-06-30` |

所有参数均为可选，不传则不过滤，**完全向后兼容**。

### 2.2 出参变更

**变更前**：rows 中只有 ID 字段，前端渲染出来全是数字。

```json
{
  "record_id": 2,
  "task_id": 2,
  "user_id": 1,
  "current_stage": "scenario",
  ...
}
```

**变更后**：新增 4 个字段，返回课题名称、创建者信息、截止时间：

| 新增字段 | 类型 | 说明 |
|---|---|---|
| `task_name` | string / null | 课题/任务名称，来自 `edu_task.task_name` |
| `creator_type` | string / null | 创建者类型：`'0'`教师创建 / `'1'`学生自建，来自 `edu_task.creator_type` |
| `creator_name` | string / null | 创建者姓名（教师或学生昵称），根据 `creator_type` 自动取 `teacher_name` 或 `student_name` |
| `deadline` | string / null | 任务截止时间，来自 `edu_task.deadline` |

**变更后示例**：

```json
{
  "record_id": 2,
  "task_id": 2,
  "task_name": "张大爷案例行动研究",
  "creator_type": "0",
  "creator_name": "张老师",
  "deadline": "2026-07-01 00:00:00",
  "user_id": 1,
  "current_stage": "scenario",
  "scenario_status": "0",
  "decision_status": "0",
  "reflection_status": "0",
  "research_status": "1",
  "scenario_id": null,
  "decision_id": null,
  "reflection_id": null,
  "research_id": 1,
  "status": "ongoing",
  "score": null,
  "teacher_feedback": null,
  "start_time": "2026-06-10 14:25:18.439112",
  "submit_time": null,
  "complete_time": null,
  "create_time": "2026-06-10 14:25:18.439112"
}
```

## 三、前端需要做的事情

### 1. 表格新增列

在记录列表表格中增加以下列（建议放在 `task_id` 列后面）：

| 列名 | 绑定字段 | 组件建议 |
|---|---|---|
| 课题名称 | `task_name` | `el-table-column`，点击可跳转到四区页面 |
| 创建者 | `creator_name` | `el-table-column` |
| 课题类型 | `creator_type` | `el-tag`，`'0'`显示蓝色"教学任务"，`'1'`显示绿色"自研课题" |
| 截止时间 | `deadline` | `el-table-column`，格式化日期 |

### 2. 搜索栏增加查询条件

建议使用 `el-form :inline="true"` 布局：

| 搜索项 | 组件 | 绑定字段 |
|---|---|---|
| 课题类型 | `el-select` | `creator_type`，选项：全部(空) / 教学任务('0') / 自研课题('1') |
| 课题名称 | `el-input` | `task_name` |
| 创建时间 | `el-date-picker type="daterange"` | 拆分为 `create_time_begin` + `create_time_end` |
| 截止时间 | `el-date-picker type="daterange"` | 拆分为 `deadline_begin` + `deadline_end` |

### 3. API 调用方式

现有 API 方法无需修改签名，查询参数直接作为 params 传入：

```javascript
// 之前
getMyRecords({ page_num: 1, page_size: 10 })

// 现在（加过滤条件）
getMyRecords({
  page_num: 1,
  page_size: 10,
  task_name: '张大爷',
  creator_type: '0',
  create_time_begin: '2026-06-01',
  create_time_end: '2026-06-30',
})
```

### 4. 不需要改的地方

- API 文件中的方法签名 **不需要修改**（查询参数都是可选的 URL query params）
- 分页逻辑 **没有变化**
- 其他接口（`/record/detail/{id}`、`/record/advance/{id}`、`/record/start/{id}`）**不受影响**

## 四、后端实现细节

### 涉及文件

| 文件 | 变更 |
|---|---|
| `module_learning/entity/vo/record_vo.py` | 新增 `RecordListQueryModel`；`RecordVO` 增加 task_name/creator_type/creator_name/deadline 字段 |
| `module_learning/dao/record_dao.py` | `get_my_records` 从单表查询改为 JOIN `edu_task` + `sys_user`（双 LEFT JOIN） |
| `module_learning/service/record_service.py` | `get_my_records` 增加 filters 参数；`_record_to_dict` 增加 task/teacher_name/student_name 参数 |
| `module_learning/controller/record_controller.py` | 入参改为 `Annotated[RecordListQueryModel, Query()]` |

### 查询方式

DAO 层使用 **双 LEFT JOIN**（和 `task_dao.get_teacher_all_tasks` 一致的模式）：

```sql
SELECT record.*, task.*, teacher.nick_name, student.nick_name
FROM edu_learning_record record
LEFT JOIN edu_task task ON record.task_id = task.task_id
LEFT JOIN sys_user teacher ON task.teacher_id = teacher.user_id
LEFT JOIN sys_user student ON task.student_id = student.user_id
WHERE record.user_id = ? AND record.del_flag = '0'
  [AND task.task_name ILIKE '%xxx%']  -- 可选
  [AND task.creator_type = '0']        -- 可选
  ...
ORDER BY record.create_time DESC
```

## 五、测试用例

### 用例1：无过滤（验证向后兼容）

```bash
curl -X GET "http://localhost:8088/learning/record/my?page_num=1&page_size=10" \
  -H "Authorization: Bearer <token>"
```

**预期**：返回所有记录，每条记录包含 `task_name`、`creator_type`、`creator_name`、`deadline` 新字段。

### 用例2：按课题类型过滤

```bash
curl -X GET "http://localhost:8088/learning/record/my?creator_type=0&page_num=1&page_size=10" \
  -H "Authorization: Bearer <token>"
```

**预期**：只返回 `creator_type='0'`（教师创建）的教学任务记录。

### 用例3：按课题名称模糊匹配

```bash
curl -X GET "http://localhost:8088/learning/record/my?task_name=张大爷&page_num=1&page_size=10" \
  -H "Authorization: Bearer <token>"
```

**预期**：只返回 `task_name` 包含"张大爷"的记录。

### 用例4：按创建时间范围查询

```bash
curl -X GET "http://localhost:8088/learning/record/my?create_time_begin=2026-06-01&create_time_end=2026-06-30&page_num=1&page_size=10" \
  -H "Authorization: Bearer <token>"
```

**预期**：只返回6月份创建的记录。

### 用例5：按截止时间范围查询

```bash
curl -X GET "http://localhost:8088/learning/record/my?deadline_begin=2026-06-01&deadline_end=2026-07-31&page_num=1&page_size=10" \
  -H "Authorization: Bearer <token>"
```

**预期**：只返回截止时间在6月到7月之间的记录。

### 用例6：组合查询

```bash
curl -X GET "http://localhost:8088/learning/record/my?creator_type=0&task_name=案例&create_time_begin=2026-06-01&page_num=1&page_size=10" \
  -H "Authorization: Bearer <token>"
```

**预期**：返回教师创建的、名称含"案例"的、6月之后创建的记录。

### 用例7：验证其他接口不受影响

```bash
# 记录详情
curl -X GET "http://localhost:8088/learning/record/detail/1" \
  -H "Authorization: Bearer <token>"

# 推进到下一区
curl -X PUT "http://localhost:8088/learning/record/advance/1" \
  -H "Authorization: Bearer <token>"
```

**预期**：这两个接口返回数据不变（不带新增的 task_name 等字段，因为它们走不同的查询路径）。
