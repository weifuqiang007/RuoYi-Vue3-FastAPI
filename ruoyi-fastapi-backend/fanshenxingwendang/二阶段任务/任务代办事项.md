# 贾维斯式督导与律师实习生助理：需求与实现路线

## 1. 文档目的

本文用于后续开发 Agent 的项目交接，记录产品目标、当前基线、系统边界、推荐架构、实施阶段、验收标准与安全要求。

目标不是继续堆叠 Live2D 展示功能，而是把 Open-LLM-VTuber 作为语音和桌面交互入口，逐步构建一个能够可靠执行以下任务的个人助理系统：

1. 作为“反身性督导”，通过结构化提问、复盘和行动追踪帮助用户工作与研究。
2. 作为“律师实习生助理”，完成语音转录、材料拆解、案件时间线、证据整理、待办生成与提醒。
3. 最终形成接近“贾维斯”的体验：常驻桌面、自然对话、主动提醒、理解上下文并调用工具完成任务。

## 2. 可行性结论

技术上可行，但 Open-LLM-VTuber 不适合作为全部业务逻辑的承载层。

推荐定位：

- Open-LLM-VTuber：语音、文字、Live2D、桌宠和会话入口。
- Assistant Core：督导工作流、案件工作区、结构化记忆和权限控制。
- MCP Tools：待办、提醒、文档、搜索、导出等可调用能力。
- DeepSeek：语言理解、分析、规划和内容生成。
- 本地数据库与文档库：事实、任务、证据、引用和审计记录的唯一可信来源。

重要原则：模型不是数据库，聊天历史也不是可靠的任务系统。所有必须长期保存或准时执行的内容都应进入结构化存储。

## 4. 产品角色

### 4.1 反身性督导

督导角色应执行固定闭环，而不是只进行开放式闲聊：

1. 接收用户对事件或困境的叙述。
2. 区分事实、解释、判断、情绪、假设和行动。
3. 发现矛盾、回避、重复模式和未验证前提。
4. 通过反身性/苏格拉底式问题推动澄清。
5. 形成会谈摘要、核心洞察、未决问题和行动承诺。
6. 将用户确认的行动写入待办系统。
7. 到期提醒，并在后续会谈中追踪执行情况。

督导输出建议采用结构化格式：

- 事实陈述
- 用户解释
- 隐含假设
- 情绪与利益相关方
- 可能的反身性模式
- 需要追问的问题
- 用户确认的行动
- 下次复盘时间

### 4.2 律师实习生助理

每个案件必须拥有独立工作区和检索范围。建议能力：

- 语音/录音转录，保留时间戳。
- 后续增加说话人分离和身份校对。
- PDF、Word、TXT、图片及扫描件导入。
- 文档 OCR、文本结构恢复、页码和段落定位。
- 提取当事人、日期、金额、请求、争议焦点和证据。
- 生成案件时间线、证据目录和材料缺口清单。
- 多份材料之间的矛盾与一致性检查。
- 生成访谈提纲、检索问题、文书框架和审核清单。
- 从谈话及材料中提取待办，并要求用户确认后写入。
