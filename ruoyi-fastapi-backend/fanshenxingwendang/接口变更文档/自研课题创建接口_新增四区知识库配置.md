# 接口变更文档：自研课题创建 - 新增四区知识库配置

> **版本**：V1.4
> **日期**：2026-06-12
> **变更人**：后端

---

## 一、接口信息

| 项目 | 内容 |
|---|---|
| **接口URL** | `POST /learning/task/student/create` |
| **接口名称** | 学生/老师自建自研课题 |
| **权限** | student / teacher / admin |
| **变更类型** | 入参变更（新增四个知识库配置字段） |

---

## 二、变更内容

### 变更前

请求体只有两个字段：

```json
{
  "task_name": "课题名称",
  "task_description": "课题描述（可选）"
}
```

### 变更后

新增 4 个可选字段，用于配置各区的知识库 ID 列表：

| 参数名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `task_name` | string | 是 | 课题名称（最大200字符） |
| `task_description` | string | 否 | 课题描述 |
| `scenario_kb_ids` | list[int] | 否 | 情境区使用的知识库ID列表，如 `[5]`；不传则后端默认 `[5]` |
| `decision_kb_ids` | list[int] | 否 | 决策区使用的知识库ID列表，如 `[5]`；不传则后端默认 `[5]` |
| `reflection_kb_ids` | list[int] | 否 | 反思区使用的知识库ID列表，如 `[5]`；不传则后端默认 `[5]` |
| `research_kb_ids` | list[int] | 否 | 研究区使用的知识库ID列表，如 `[5]`；不传则后端默认 `[5]` |

**默认值逻辑**：四个 `*_kb_ids` 字段如果前端不传或传 `null`，后端自动填充默认公用知识库 ID `[5]`。

### 出参

**无变化**，仍返回 `{ "task_id": <int> }`。

### 2. 新增知识库列表加载逻辑

从 `@/api/rag/knowledgeBase` 导入 `listKnowledgeBase`，在弹窗打开时加载知识库选项列表。

### 3. 修改 `submitSelf` 提交数据

```javascript
// 之前
await createStudentTask({ task_name: name, task_description: desc || undefined })

// 现在
await createStudentTask({
  task_name: name,
  task_description: desc || undefined,
  scenario_kb_ids: selfScenarioKbIds,
  decision_kb_ids: selfDecisionKbIds,
  reflection_kb_ids: selfReflectionKbIds,
  research_kb_ids: selfResearchKbIds,
})
```

### 4. 默认值设置

弹窗打开时，四个知识库字段默认选中 `[5]`（公用知识库）。

### 5. 不需要改的地方

- API 文件 `api/learning/task.js` 中的 `createStudentTask` 方法 **不需要修改**（只是传入更多字段）
- 后端接口 **完全向后兼容**，不传知识库字段也能正常创建（自动填默认值）

## 四、测试用例

### 用例1：不传知识库字段（验证向后兼容 + 默认值）

```bash
curl -X POST "http://localhost:8088/learning/task/student/create" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"task_name": "测试课题", "task_description": "测试描述"}'
```

**预期**：创建成功，返回 `{ "task_id": <int> }`。数据库中该任务的 `scenario_kb_ids`、`decision_kb_ids`、`reflection_kb_ids`、`research_kb_ids` 四个字段均为 `[5]`。

### 用例2：传自定义知识库配置

```bash
curl -X POST "http://localhost:8088/learning/task/student/create" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"task_name": "测试课题2", "scenario_kb_ids": [5], "decision_kb_ids": [5], "reflection_kb_ids": [5], "research_kb_ids": [5]}'
```

**预期**：创建成功，数据库中四个知识库字段均为 `[5]`。

### 用例3：传空数组（明确不使用任何知识库）

```bash
curl -X POST "http://localhost:8088/learning/task/student/create" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"task_name": "测试课题3", "scenario_kb_ids": []}'
```

**预期**：创建成功，`scenario_kb_ids` 为 `[]`（空数组，不使用知识库），其余三个字段为默认值 `[5]`。

### 用例4：创建后进入四区验证

```bash
# 1. 创建自研课题
curl -X POST "http://localhost:8088/learning/task/student/create" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"task_name": "四区验证课题"}'

# 2. 开始任务
curl -X POST "http://localhost:8088/learning/record/start/<task_id>" \
  -H "Authorization: Bearer <token>"

# 3. 查看任务详情，确认 kb_ids 已填充
curl -X GET "http://localhost:8088/learning/task/detail/<task_id>" \
  -H "Authorization: Bearer <token>"
```

**预期**：任务详情中 `scenario_kb_ids`、`decision_kb_ids`、`reflection_kb_ids`、`research_kb_ids` 均为 `[5]`，不再是 `null`。
