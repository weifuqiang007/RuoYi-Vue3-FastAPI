# 接口变更文档：任务创建/更新 - 新增批阅（裁判）模型配置

> **版本**：V1.0
> **日期**：2026-06-17
> **变更人**：后端
> **关联设计**：`四区研究实现逻辑/教师批阅反思研究模块_设计方案.md`

---

## 一、涉及接口

| 项目 | 内容 |
|---|---|
| 接口URL | `POST /learning/task/create`、`PUT /learning/task/update`、`POST /learning/task/student/create` |
| 接口名称 | 创建教学任务 / 编辑任务 / 自建自研课题 |
| 权限 | teacher / admin（create、update）；student / teacher / admin（student/create） |
| 变更类型 | **入参变更**（三个接口统一新增 `review_model_id` 字段） |

---

## 二、变更原因

批阅（裁判）AI 模型与学生侧四区（情境/决策/反思/研究，固定 `model_id=1`）**必须使用不同模型**，避免「自己既当发牌员又当裁判」——否则等于模型评价自己（或同模型兄弟）的产出。

`review_model_id` 挂在任务上，由老师创建/编辑任务时配置；自研课题同样可配。

---

## 三、变更内容

三个接口请求体统一新增 1 个可选字段：

| 参数名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `review_model_id` | int | 否 | 批阅（裁判）AI 模型 ID，关联 `ai_model.model_id`；为空时回落系统默认批阅模型（`sys_config: edu.review.default_model_id`）；**必须 ≠ 学生侧模型（1）** |

**完全向后兼容**，不传该字段也能正常创建/更新（批阅时回落系统默认）。

### 请求示例

```bash
# 教师创建任务，指定批阅模型 model_id=3
curl -X POST "http://localhost:8088/learning/task/create" \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"task_name":"张大爷案例","scenario_kb_ids":[5],"review_model_id":3}'

# 学生创建自研课题，不指定批阅模型（回落系统默认）
curl -X POST "http://localhost:8088/learning/task/student/create" \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"task_name":"我的研究"}'
```

---

## 四、出参变更

任务详情 `GET /learning/task/detail/{task_id}`、任务列表返回数据中**新增 `review_model_id` 字段**（int / null）。

---

## 五、前端需要做的事情

1. `views/learning/task/components/TaskFormDialog.vue`（教师任务表单）：在「各区知识库配置」区下方新增「**批阅模型**」下拉，选项来自 AI 模型列表接口（`/ai/model/list`），**可空**；placeholder 提示「不选则使用系统默认批阅模型（须 ≠ 学生侧模型）」。
2. `StudentTaskList.vue` 自研课题弹窗同步加该下拉。
3. `createTask` / `updateTask` / `createStudentTask` 提交时携带 `review_model_id`（API 方法签名无需改，仅多传一个字段）。

---

## 六、部署前置（重要）

上线前管理员须在「参数设置」中把 `edu.review.default_model_id` 的值改成**实际存在且 ≠1** 的模型 ID（建表脚本默认占位 `2`）。否则老师未单独配置时批阅会报错「未配置批阅模型」。
