## 二、问题描述

### 问题1：前端请求超时

- **现象**：点击"生成分析"按钮后，前端报"接口超时"
- **原因**：前端 axios 全局超时为 10 秒，但 AI 伦理分析需要 RAG 知识检索 + LLM 生成，实际耗时 30-60 秒
- **修复**：前端 `ethicsAnalyzeDecision` 接口单独设置 `timeout: 120000`（120 秒）

### 问题2：分析结果展示不友好

- **现象**：AI 返回的 JSON 结果以 `<pre>{{ JSON.stringify }}</pre>` 原始格式展示，学生看不懂
- **原因**：`EthicsPanel.vue` 直接将 JSON 字符串输出到页面
- **修复**：重写 `EthicsPanel.vue`，用结构化卡片展示：
  - 📋 **综合分析**：段落文本，浅灰背景卡片
  - ⚖️ **伦理维度分析**：每个维度一张卡片，`支持` 绿色标签 / `张力` 橙色标签
  - 📖 **相关伦理守则**：每条守则一张卡片，标注来源和关联说明
  - 🤔 **进一步思考**：蓝色背景列表，带问号图标

### 问题3：后端错误信息不够友好

- **现象**：异常时返回原始 error stack，前端显示不友好
- **修复**：
  - `decision_service.py`：RAG 检索失败不再抛异常，降级为空知识上下文；LLM 调用失败抛明确错误信息
  - `decision_controller.py`：区分 `ValueError`（业务错误）和其他异常，返回友好提示
  - 添加全链路日志（知识检索 → LLM 调用 → 结果保存）

## 三、变更内容

### 后端变更

| 文件 | 改动 |
|---|---|
| `decision_service.py` | `ethics_analyze` 方法增加日志、RAG 检索降级容错、LLM 失败明确报错 |
| `decision_service.py` | `_retrieve_ethics_knowledge` 异常时打印警告日志 |
| `decision_controller.py` | `ethics_analyze` 接口区分 ValueError 和通用异常，返回友好提示 |

### 前端变更

| 文件 | 改动 |
|---|---|
| `api/learning/decision.js` | `ethicsAnalyzeDecision` 增加 `timeout: 120000` |
| `decision/components/EthicsPanel.vue` | 全部重写，结构化卡片展示分析结果，增加加载中动画 |

### 出参格式（无变化）

AI 分析返回的 JSON 结构不变，仍为：

```json
{
  "analysis": "综合分析文本",
  "relevant_codes": [...],
  "ethics_dimensions": [...],
  "further_questions": [...]
}
```

只是前端从 `<pre>` 原始 JSON 改为结构化渲染。

## 四、前端需要做的事情

**已在本次修改中完成**，无需额外操作。主要改动：

## 五、测试用例

### 用例1：正常生成分析

1. 进入决策区，填写决策记录并保存
2. 点击「生成分析」按钮
3. **预期**：页面显示加载动画（约30-60秒），然后结构化展示分析结果，不再超时

### 用例2：知识库未配置时的降级

1. 创建一个自研课题（不配知识库，后端会填默认 `[5]`）
2. 进入决策区保存记录 → 点击「生成分析」
3. **预期**：即使知识库检索失败，也能正常生成分析（知识参考为空），不报错

### 用例3：LLM 服务不可用

1. 模拟 LLM 服务异常
2. 点击「生成分析」
3. **预期**：前端收到友好错误提示"AI分析服务暂时不可用，请稍后重试"，而非原始异常栈

### 用例4：分析结果展示验证

1. 正常生成分析后，检查页面四个区域：
   - 📋 综合分析：段落文本，可读性强
   - ⚖️ 伦理维度：每个维度有名称、立场标签（绿色"支持"/橙色"张力"）、描述
   - 📖 相关伦理守则：每条有来源标签、守则名称、关联说明
   - 🤔 进一步思考：编号列表，蓝色背景
2. **预期**：各区域内容清晰可读，学生能直观理解 AI 分析结果
