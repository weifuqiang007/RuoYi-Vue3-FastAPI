# 反思区「生成理论指导」三个 Bug 的问题原因与改造方案

> 模块：学习区 → 反思区（reflection）
> 涉及接口：`POST /learning/reflection/questions/stream`（流式生成理论指导）
> 编写日期：2026-06-17
> 状态：**待确认**（确认后再改代码）

---

## 一、问题现象

| Bug | 现象 |
|-----|------|
| Bug 1 | 点击「生成理论指导」后，「反思方向」里直接显示出 Markdown 原始语法符号，如 `####1`、`**赋权理论（Empowerment Theory）**`。看起来像「Markdown 文本被当成 JSON 字符串原样输出了」。 |
| Bug 2 | 「反思方向」的内容被截取了，用户希望**全部展示**，不要截断。 |
| Bug 3 | 点击「生成理论指导」后，底部「关联理论总览」模块**没有任何内容生成**。不确定是没生成、没渲染，还是接口不对。 |

---

## 二、数据流梳理（先看懂链路，再定位问题）

「生成理论指导」是一次**流式（SSE）**请求，完整链路如下：

```
[前端] DecisionReflectionTab.generateGuidance()
   │  调 generateReflectionQuestionsStream()  →  fetch POST /learning/reflection/questions/stream
   ▼
[后端] ReflectionService.generate_questions_stream()
   │  1. 拼 REFLECTION_STREAM_PROMPT（要求 LLM：先输出可读 Markdown，最后用 ```json 块输出结构化结果）
   │  2. yield status / content（逐字把 Markdown 转发给前端）
   │  3. 流结束后：_parse_streamed_guidance(full_text) 解析出结构化 dict
   │  4. _persist_guidance() 落库（写 dialogue + reflection.linked_theories + 深度历史）
   │  5. yield result（把结构化 dict 发给前端）
   ▼
[前端] onResult(data)
   │  latestGuidance.value = data
   │  streamText.value = ''   ← ★ 生成结束就把流式预览的 Markdown 原文清空
   │  emit('guidance-generated', { theories: data.theory_guidance || data.theories || [] })
   ▼
[渲染] 用 latestGuidance 的字段渲染「关联理论 / 反思方向 / 追问」
        父组件 reflection/index.vue 用 emit 的 theories 渲染底部「关联理论总览」
```

**一个关键体验落差**：流式生成**进行中**时，前端 `displayStreamText` 会剥离结尾的 ```json 块，展示的是一段**完整漂亮的 Markdown**（含深度评估、关联理论、反思方向、追问）。但生成**一结束**，`onResult` 把 `streamText` 清空，改用结构化的 `latestGuidance` 渲染。如果结构化解析失败，用户就从「漂亮的 Markdown」瞬间退化成「带语法符号的截断文本」。

## 三、根因分析

### 3.1 核心：后端兜底分支（三个 Bug 的共同根源）

`module_learning/service/reflection_service.py` 的 `_parse_streamed_guidance`（第 295–331 行）：

```python
@classmethod
def _parse_streamed_guidance(cls, full_text: str) -> dict:
    # ① 取最后一个 ```json 代码块
    blocks = re.findall(r'```json\s*(.*?)```', full_text, re.DOTALL)
    candidate = blocks[-1].strip() if blocks else full_text
    try:
        parsed = parse_llm_json(candidate)
        if isinstance(parsed, dict) and parsed:
            return parsed
    except Exception:
        pass

    # ② 整体再试一次
    try:
        parsed = parse_llm_json(full_text)
        ...
    except Exception:
        pass

    # ③ 兜底：★ 问题就在这里 ★
    return {
        'depth_score': score,
        'depth_level': level,
        'theory_guidance': [],                                    # ← 空！Bug 3
        'reflection_direction': full_text.strip()[:500] or '...', # ← 截断！Bug 2，且带 Markdown 语法 Bug 1
        'questions': [],
    }
```

当 ①② 都解析失败时，走 ③ 兜底：
- `theory_guidance = []` → 父组件 `allTheories` 为空 → **Bug 3 关联理论总览无内容**
- `reflection_direction = full_text[:500]` → 整段 Markdown 正文（含 `####`、`**`）被塞进一个字符串字段，并被截到 500 字 → **Bug 1 显示语法符号 + Bug 2 被截取**

**为什么会走到兜底？** 可能原因：

1. LLM 没严格按 prompt 在结尾输出闭合的 ```json ... ``` 块（漏了结束 ```，或用了 ```jsonl 等变体）。
2. 正则 `r'```json\s*(.*?)```'` 会匹配正文里**任意** ```json 块（比如 LLM 举例时也写了一个），`blocks[-1]` 取到的可能不是最终结构化结果，导致解析失败。
3. JSON 字段值里含未转义的换行/引号，`json.loads` 失败。
4. 流被中途打断，`full_text` 不完整。

> 从现象判断（出现 `####1`、多个 `**理论名**`，说明整段 Markdown 正文被塞进了 `reflection_direction`），**当前大概率就是走了兜底分支**。需按「四、诊断方法」确认。

### 3.2 Bug 1 的另一层独立根因：前端用纯文本渲染 LLM 文本

即便解析**成功**，LLM 也可能在结构化字段的**值**里继续用 Markdown 语法（如 `"theory_name": "**赋权理论**"`、`"suggestion": "建议...\n- 要点1\n- 要点2"`）。

而前端所有展示 LLM 文本的地方都用 `{{ }}` 文本插值，**不解析 Markdown**：

| 文件 | 位置 | 问题代码 |
|------|------|----------|
| `DecisionReflectionTab.vue` | L42, L46, L49, L56 | `{{ g.theory_name }}`、`{{ g.relevance }}`、`{{ g.suggestion }}`、`{{ latestGuidance.reflection_direction }}` |
| `ReflectionRoundCard.vue` | L39, L48, L49, L56 | `{{ parsedContent.reflection_direction }}` 等（历史轮次） |
| `AiQuestionPanel.vue` | L34, L37, L48 | 同上（另一套未启用的卡片，但同样问题） |
| `TheoryLinkage.vue` | L8, L12, L15 | 关联理论总览 |

`{{ }}` 会把 `**`、`####`、`-` 当普通字符显示。所以**无论是否走兜底，前端都必须改成 Markdown 渲染**才能根治 Bug 1。

> 注：`ReflectionRoundCard.vue` L34 的 `formatText` 只把 `\n` 换成 `<br>`，不处理 `**`、`#` 等语法，同样不够。

### 3.3 Bug 2 的截取点

唯一的截取点就是兜底分支的 `[:500]`（`reflection_service.py:329`）。
- 前端 `.direction-text` / `.content-text` 都**没有** max-height 或 JS 截断。
- 若解析成功，`reflection_direction` 是 LLM 写的完整字符串，不会被截。

所以 Bug 2 的根因有两条：
1. **主因**：走兜底 → `[:500]` 截断（与 Bug1/3 同源）。
2. **产品语义**：如果期望「反思方向」区块展示的是**完整 Markdown 理论指导**（含理论/方向/追问全部），当前结构化拆分后只剩 `reflection_direction` 一句，正文被丢弃 → 需要方案三（保留原文渲染）。

### 3.4 Bug 3 的完整排查

「关联理论总览」= `TheoryLinkage` 组件，数据源是 `reflection/index.vue` 的 `allTheories`（L108–123），聚合自 `tabStates[decisionId].theories`。`theories` 有两个填充时机：

1. **生成时**：`DecisionReflectionTab` 的 `onResult` → `emit('guidance-generated', { theories: data.theory_guidance || data.theories || [] })` → 父组件 `onTabGuidanceGenerated` 写入 `tabStates`。
   - 走兜底时 `data.theory_guidance = []` → **空，Bug 3 出现**（同源）。
2. **加载时**：`loadData()` 从 `reflection.linked_theories` 取（L163）。落库链路 `_persist_guidance`（L355）写入 `linked_theories` 没问题，`_reflection_to_dict`（L466）也正常返回。

**结论**：Bug 3 不是「接口不对」也不是「没渲染」，而是**生成时 `theory_guidance` 为空数组**（兜底导致），所以聚合后自然无内容。接口和渲染逻辑本身是对的。

## 四、诊断方法（改代码前建议先确认根因）

按以下顺序确认「到底是不是走了兜底分支」：

1. **看 Network**：打开浏览器 F12 → Network → 触发一次「生成理论指导」→ 找到 `/questions/stream` 请求 → 在 Response 里看最后一条 `{"type":"result","data":{...}}`：
   - 若 `data.theory_guidance` 是 `[]` 且 `data.reflection_direction` 是一大段含 `####`/`**` 的文本 → **确认走了兜底**（核心根因坐实）。
   - 若 `data.theory_guidance` 有值但字段值里带 `**` 等 → 是「解析成功但 LLM 在值里用了 Markdown」，只需前端渲染修复。

2. **看数据库**：查 `edu_reflection_dialogue` 表最近一条 `role='assistant'` 的 `content`：
   - 是合法 JSON（含 theory_guidance 数组）→ 解析成功。
   - 是一大段 Markdown 文本或 `{theory_guidance:[], reflection_direction:"####..."}` → 走了兜底。

3. **加后端日志**（建议无论哪种都加上，便于后续排查）：在 `_parse_streamed_guidance` 的兜底 return 前打印 `logger.warning('[反思区] JSON解析失败，走兜底分支, full_text长度=%d, 前200字=%s', len(full_text), full_text[:200])`。当前流式路径**没有任何解析结果日志**（只有非流式 `generate_questions` 打了），排查很被动。

## 五、改造方案

分「必须改」和「建议改」。建议**前端 + 后端一起改**才能根治。

### 方案一（前端 · 必须改）：引入 Markdown 渲染

项目 `package.json` 当前**没有** Markdown 库，需安装。推荐 **`marked` + `dompurify`**（轻量、可控、防 XSS）：

```bash
pnpm add marked dompurify
# 或 npm i marked dompurify
```

封装一个通用渲染组件 / 指令，例如 `src/components/MarkdownView/index.vue`：

```vue
<template>
  <div class="md-view" v-html="html"></div>
</template>
<script setup>
import { computed } from 'vue'
import { marked } from 'marked'
import DOMPurify from 'dompurify'
const props = defineProps({ content: { type: String, default: '' } })
marked.setOptions({ breaks: true, gfm: true })
const html = computed(() =>
  DOMPurify.sanitize(marked.parse(props.content || '')))
</script>
```

然后把下表所有 `{{ lLM文本字段 }}` 替换为 `<MarkdownView :content="..." />`：

| 文件 | 行 | 字段 |
|------|----|------|
| `DecisionReflectionTab.vue` | 42 | `g.theory_name` |
| `DecisionReflectionTab.vue` | 46 | `g.relevance` |
| `DecisionReflectionTab.vue` | 49 | `g.suggestion` |
| `DecisionReflectionTab.vue` | 56 | `latestGuidance.reflection_direction` |
| `ReflectionRoundCard.vue` | 39 / 48 / 49 / 56 | 历史轮次的反思方向、理论关联/建议、追问 |
| `AiQuestionPanel.vue` | 34 / 37 / 48 | （如仍在使用） |
| `TheoryLinkage.vue` | 8 / 12 / 15 | 关联理论总览的理论名/关联/建议 |

> 用户要求「反思方向显示**带背景样式**的图书样式」：保留现有 `.direction-text { background:#ecf5ff; ... }` 卡片背景，内部用 `<MarkdownView>` 渲染即可，外层背景不变。

### 方案二（后端 · 必须改）：去掉截断 + 兜底也提取理论

`reflection_service.py`：

1. **移除 `[:500]` 截断**（Bug 2 直接修复）：
   ```python
   'reflection_direction': full_text.strip() or '（未生成可读内容）',
   ```

2. **增强 ```json 块提取鲁棒性**：优先取「含 `theory_guidance` 或 `depth_score` 关键字」的块，避免误匹配正文里的示例代码块：
   
   ```python
   blocks = re.findall(r'```(?:json)?\s*([\s\S]*?)```', full_text)
   candidates = [b.strip() for b in blocks if 'theory_guidance' in b or 'depth_score' in b]
   candidate = (candidates[-1] if candidates else (blocks[-1].strip() if blocks else full_text))
   ```
   
3. **兜底分支也尽量提取理论**（缓解 Bug 3）：用正则从全文抓 `**xxx理论**` / `**xxx（...）**` 模式，拼成 `theory_guidance`，而不是直接给空数组。

4. **加解析日志**（见第四节第 3 点）。

### 方案三（增强 · 建议）：保留完整 Markdown 原文渲染

解决「生成结束后漂亮内容消失」的体验落差。两种做法二选一：

- **做法 A（推荐，纯前端）**：`DecisionReflectionTab` 在 `onResult` 里**不清空** `streamText`，生成结束后「AI 理论指导」区块优先用 `displayStreamText`（完整 Markdown）渲染，结构化字段仅用于「关联理论总览」聚合和深度分数。这样即使后端解析失败，用户也能看到完整指导。
- **做法 B（后端）**：流式 result 里同时返回 `markdown_text`（完整可读正文）和结构化字段，前端任选其一渲染。需改 `generate_questions_stream` 的 result yield 和 `_parse_streamed_guidance` 返回值。

## 七、风险与兼容性

| 项 | 说明 |
|----|------|
| `v-html` + XSS | 必须用 `DOMPurify.sanitize` 包裹，LLM 输出不可信。不可直接 `v-html="marked(...)"`。 |
| 依赖新增 | `marked` + `dompurify` 体积小（合计 ~50KB gzip），对打包影响有限。 |
| 后端解析改动 | 只改兜底与正则，不影响解析成功的正常路径；建议改完后用历史 dialogue 数据回归一次。 |
| 历史数据 | 走兜底落库的旧 dialogue（`theory_guidance=[]`）不会自动修复，需重新点「生成理论指导」覆盖。 |
| `AiQuestionPanel.vue` | 该组件当前似乎未被 `reflection/index.vue` 引用（实际用的是 `DecisionReflectionTab`），改前请确认是否仍在使用，避免无效改动。 |
